# vm2 — трансляция копикода для emulator

В монорепозитории результаты находятся в общем `../../build/`, пути Makefile
выбираются автоматически. Общие команды из корня: `make -j1`,
`./tools/run/forth`, `make -j1 check`. Примеры с локальными `build/` и `dist/`
ниже относятся к самостоятельному распакованному выпуску; в workspace
для Forth используйте общий запускатель. Каталог legacy/ не требуется.


Целевая реализация — Forth-скрипты внутри пространства. Текущий Python-путь
сохраняется до приёмки замены. Загрузку/выгрузку, trace и снимки переносим
на гостевой Forth; хостовый запуск и реальные файловые/терминальные операции
принадлежат emulator. [План и границы переноса](doc/migration-forth.md).

Основной путь — `vm2c`: символический копикод `[n,dst,src]` один раз
транслируется в сохранённые псевдоинструкции emulator. Готовый образ исполняется
непосредственно emulator; обновления описаний выполняются в пространстве.
[Целевой ABI, SDK, ограничения и проверки](doc/direct.md).

Отдельный запускатель `vm2` сохраняет совместимость с прежними упакованными
тройками, включая 47-битный формат при S=65520. Он исполняет интерпретатор
в пространстве emulator. Автоматического перехода между ABI нет.

```sh
make                         # build/direct-example/{image,boot,map,manifest}
./vm2c compile examples/direct/hello.json -o /tmp/vm2-hello
./vm2c run /tmp/vm2-hello
make check-direct            # прямой путь, независимый эталон, аудит операндов
make guest                   # совместимый интерпретатор -> build/vm2.boot
./vm2 -s 65520 -p 64 -t 0 < boot.bin
make check                   # независимый эталон + фактический запуск emulator
make distcheck               # автономный архив с точными снимками зависимостей
```

Зависимости: Python 3.11+, Linux/POSIX, [emulator](../../emulator/README.md) с ABI rev1 и
[copycode](../copycode/README.md). `EMULATOR` задаёт путь к бинарнику;
`EMULATOR_ROOT` и `COPYCODE_ROOT` — исходники для сборки/проверок. По умолчанию
используются соседние проекты copymachine; в исходном архиве — vendor/.
Механизм emulator выбирается при его сборке. Текущий размер микрокода требует
bitcopy: профиль network до 65520 позиций его не вмещает. Автоматической
смены механизма нет.

`-s/-p/-t` относятся к **vm2**; значения по умолчанию — 65520/64/0.
Первый активный виртуальный такт выполняет исходный stdin seed vm2.
Ноль тактов означает работу до NOP. Запускатель добавляет только загрузку
интерпретатора; затем гостевой поток stdin идёт без преобразования инструкций.
Поддерживаются живые pipes и seekable regular files. Для файлов запускатель
создаёт временную конкатенацию, а копикод переводит SEEK_SET/FSTAT обратно
в координаты исходного гостевого потока. Одновременное внешнее изменение
такого файла и наблюдение общей с родителем позиции fd не поддерживаются.

Скомпилированный интерпретатор кэшируется по исходникам, зависимостям и
конфигурации. Каталог: VM2_CACHE либо $XDG_CACHE_HOME/copymachine/vm2
(по умолчанию ~/.cache/copymachine/vm2). При `make` это build/guest-cache.
Проверяется SHA256 кэша; повреждённый код не запускается.

[планировщик и измерения ускорения](doc/vm2-scheduling.md),
[контракт vm2](doc/emulator-contract.md), [сборка](doc/build.md),

Прежний C-путь `space` сохранён только для миграции существующих потребителей
и сравнений: `make legacy`, `make check-legacy`, `make check-core`. Он не
выбирается запускателем vm2 и не входит в установленный продукт. Независимый
эталон новой реализации — небольшой tests/vm2_reference.py. Общие
boot/SYS/monitor/checkpoint/transport принадлежат copycode, не vm2/tools.
