# Владение исходниками после этапа 4

Целевое разделение уточнено: реализация vm2 переносится на Forth,
хостовые адаптеры принадлежат emulator. Текущая таблица описывает рабочий
Python-путь до приёмки замены; [план переноса](migration-forth.md).

| Владелец/путь | Ответственность |
|---|---|
| emulator | Единственный поддерживаемый хостовый эмулятор, 4 индекса, SYS и каналы |
| vm2/vm2compile | Постоянная трансляция символического копикода, прямой ABI, артефакты, SDK и адаптер legacy |
| vm2/vm2guest | Гостевой процессор троек, арифметика/канальные преобразования и запуск |
| vm2/tests/vm2_reference.py | Небольшой независимый побитовый эталон vm2 |
| vm2/tests/checked_vm1.c | Независимая проверка фактических физических расписаний; не продукт |
| copycode | Общие boot/SYS/monitor/checkpoint/transport и библиотеки; vm2/tools — переходники |
| copy-space и будущие rv32i/pforth/copy-c/gcc | Приложения, их перепланирование и сквозная проверка |

Корневые C-исходники vm2 и команда space временно сохранены как явный legacy
контроль и путь миграции существующих потребителей, до выполнения последующих
этапов. Основные make/CLI/install не выбирают этот C-эмулятор. Новые функции
хостового эмулятора здесь не добавляются.

Исходный архив явно включает точные снимки зависимостей emulator/copycode с
SHA256 всех файлов; это воспроизводимый комплект выпуска, не новые владельцы
их исходников. Установленный vm2 содержит свой Python-генератор и копию
объявленного Python-пакета copycode с лицензиями, а emulator вызывается отдельно.
Гостевые инструкции хостом не интерпретируются.

Термины: копикод — тройки `[n,dst,src]`; четыре границы emulator —
псевдоинструкции, описывающие каналы передачи битового сигнала. Текущие
Python API emulator с именами instruction/copycode сохранены ради совместимости;
они обозначают целевые псевдоинструкции, не альтернативный формат троек.
