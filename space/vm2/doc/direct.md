# Постоянная трансляция копикода

Копикод — инструкции `[n,dst,src]`. Псевдоинструкция emulator — четыре границы
`[dst_low,dst_high,src_low,src_high]`: описание канала передачи сигнала
между двумя полуинтервалами памяти. В информационном смысле источник
передаёт биты назначению. Это описание связи, а не утверждение о пропускной
способности физического устройства. Потоковые stdin/stdout и управляющий
SYS — отдельные устройства с собственным протоколом.

`vm2c` выпускает новый целевой ABI `vm2-direct-v1`. Он не обещает побайтовой
совместимости кода со старыми тройками. Старые образы, произвольные сырые
записи в код и старые снимки запускаются явно через `vm2`; C-контроль
доступен через `make legacy`. Неподдерживаемый символический исходник
отклоняется без скрытого выбора интерпретатора. Полный RV32I переносится
на следующем этапе; здесь проверен фрагмент его настоящих генераторов.

```sh
make
./vm2c compile examples/direct/hello.json -o /tmp/hello-direct
./vm2c check /tmp/hello-direct
./vm2c run /tmp/hello-direct
./vm2c run /tmp/hello-direct --physical-ticks 100
./vm2c resume /tmp/hello-direct snapshot.bin -o /tmp/resumed-direct
```

Каталог результата должен быть новым. После сборки исходник можно удалить:
для check/run/resume компилятор не импортируется. `EMULATOR` задаёт бинарник emulator;
его backend выбирается при сборке emulator. `make install` устанавливает оба
запускателя и необходимые библиотеки; отдельная установка emulator обязательна.

## Символы, размещение и артефакт

Публичный Python API находится в `vm2compile`: `Program`, `Copy`, `Memory`,
`Field`, `Channel`, `Replace`, `Value`, `LayerBits`, `SysWidth`.
`Program.source()` и `Program.load()` сериализуют `vm2-symbolic-v1`.
Данные имеют имя, размер, выравнивание и необязательные типизированные
релокации. `Value('data',name,offset)` — адрес данных;
`Value('entry',layer)` — адрес слоя после размещения;
`Value('channel','stdout')` — адрес устройства. `Program.record` и SDK
размещают именованные поля записей после выбора ширины адреса.
`Memory(name,offset)` допускает смещение в битах или имя поля записи.

`Program.layer(name,copies,next=...)` задаёт логический слой.
`next` — имя слоя, типизированный указатель в памяти или None (остановка).
`Program.slots` сохраняется как характеристика исходника; число физических
слотов выбирает backend из размера развёрнутого слоя. `size` задаёт
минимальный размер памяти; при нехватке места он увеличивается. Флаг
`--exact-size` запрещает увеличение. Условия независимости интервалов,
включая src/src, проверяются до исполнения; дополнительные физические
слои планирует общий backend copycode. Пользовательское копирование с
конфликтующими операндами отклоняется, а не сериализуется незаметно.

Обычная операция превращается в `[dst,dst+n,src,src+n]`. Нулевая длина
даёт NOP. Проверяются размеры, границы регионов, переполнение полей,
пересечения и типы ссылок. Адреса кода числом не принимаются.
Размеры полей задаются символически: `'address'`, `'count'`, `LayerBits()`.
`Field(layer,slot,'n'|'dst'|'src',offset)` адресует логический битовый срез.

Артефакт содержит `image.bin`, `boot.bin`, `manifest.json`, `map.json`.
Манифест фиксирует ABI, S/P, ширины и порядок битов, точку входа, исходный
хеш, хеши зависимостей и SHA256 каждого файла. Карта данных, слоёв,
логических полей и обновлений отделена от исполняемого образа.
Загрузка отклоняет неверный ABI, состав, длины и хеши файлов.
Контрольные суммы предназначены для проверки целостности, не аутентификации.
`boot.bin` — обычный stdin seed emulator; emulator не знает о трансляторе.

## Изменение кода и границы слоёв

Состояние `n/dst/src` сохраняется только для описаний, которые читаются,
меняются или участвуют в такой замене. Полной теневой копии троек нет.
Неизменный слой исполняется непосредственно из готовых псевдоинструкций.
Чтение Field возвращает логическое поле; физические границы не являются
его старой упаковкой. Экспорт старой упаковки не входит в этот ABI.

Все исходные операнды слоя читаются до его эффектов. Патч текущего слоя
влияет на следующий вход в него. Изменения одного описания группируются:
dst/src обновляют соответствующие нижнюю и верхнюю границы; n меняет
верхние границы. Для выровненной LUT с неизменной длиной проверка переноса
позволяет копировать только нужные срезы обеих границ. Иначе сумматоры
в пространстве пересчитывают затронутые границы. Для общего динамического
случая строится явная последовательность классификации каналов и границ.

После эффекта слоя исполняются все его обновления, затем переход.
Следующий логический слой не может увидеть частично готовое описание.
Физический такт emulator и логический слой различаются; `Program.limit` считает
логические слои, `--physical-ticks` — такты emulator вместе с загрузкой.
Частичная остановка физическим лимитом не является checkpoint.

`checkpoint_stop=True` вместе с checkpoint останавливает текущий процесс
после снимка. В снимке остаётся объявленное продолжение следующего слоя,
поэтому resume не повторяет уже завершённый слой. Это общий механизм
кооперативной паузы, используемый монитором RV32I; сам счётчик RV32I не
принадлежит vm2. Внешние позиции каналов по-прежнему восстанавливает вызывающий.

`Replace(dst,src)` копирует уже целевой слой и нужные логические поля.
Слои должны содержать одинаковое число Copy; продолжение копируется вместе
с шаблоном. Поддерживаются шаблоны со статическим продолжением, без собственных
записей Field, checkpoints и логического лимита; остальные отклоняются,
поскольку их служебные последовательности привязаны к исходному слою.
SDK `construct` строит описание в существующем типизированном слоте:
значения — Memory/Field или релокации Value, обновление завершается до
использования нового слоя. Создание произвольного нового графа слоёв,
смена ширины/назначения самой операции записи Field и запись сразу через
несколько описаний не поддерживаются. Их нужно выразить другим исходником.

Динамические значения обязаны давать допустимые непересекающиеся операнды,
представимые длины и адреса, как в контракте emulator. Компилятор не доказывает
произвольные значения входных данных. Тестовый checked-emulator проверяет
фактические патченные операнды каждого такта, включая src/src и fetch.
Ядро emulator не следит за изменениями и не запускает хостовый транслятор.

## Устройства и восстановление

Channel задаёт устройства sys/stdin/stdout/debug/status/snapshot.
Канал кодируется парой `[C,C]`; прибавление длины к адресу устройства
запрещено. Обычные потоки округляют буфер вверх до полного байта.
SYS использует нативную ширину emulator из proto.def; `sdk.sys_record`,
`request`, `response` строят записи и операции. Ответ, прочитанный в слое
запроса, старый; новый доступен следующему слою после принятой границы.
`stdin_position(offset)` явно учитывает загрузочный префикс для SEEK_SET.
Живой pipe не ждёт EOF перед запуском; regular stdin сохраняет seekability
через временный составной файл. SYS-записи старого ABI надо пересобрать.

`checkpoint=True` сохраняет согласованное состояние после обновлений слоя
на fd4: процессор содержит продолжение, затем идут остальные байты памяти.
`resume` проверяет размер, ABI и неизменную часть кода, заново упаковывает
stdin seed и релокации его начала. Исходник не нужен. Внешние позиции файлов,
закрытые устройства и процессы не входят в память: их восстанавливает
вызывающая сторона. Сырые снимки старого vm2 несовместимы.

## Передача RV32I и гостевым компоновщикам

`vm2compile.legacy.adapt` принимает незакодированные блоки Copy/Field и
явно объявленные регионы от владельца генератора. Поля и ссылки на
переходы становятся символическими; физические адреса пересчитываются.
Логические адреса гостевой памяти и формат её байтов сохраняет владелец.
Необъявленные raw-адреса отвергаются. Частичные адресные патчи требуют
сохранения выравнивания; адаптер проверяет и переносит это требование.
Операции legacy фрагмента сериализуются, поэтому его старые конфликты src/src
не попадают в новый ABI. Полный перенос и упаковка RV32I остаются этапом 7.

`tools/direct_prototype.py` воспроизводит `examples/direct/rv32i-fragment.json`
из memory_address, lookup и jump настоящего copy-space/modules/rv32i.py.
Фрагмент загружает слово RV32I, использует LUT с патчем адреса, пишет память,
выполняет косвенный переход и выдаёт результат. Это проверка ABI транспорта
и диспетчеризации, а не исполнение полного набора инструкций RV32I.

Для будущих гостевых copy_emit/copy_link входным контрактом служат те же
типы данных, слоёв, полей и релокаций. Компоновщик выбирает S/P/A, размещает
данные и шаблоны, разрешает Value, проверяет все интервалы, выпускает
четыре границы и явные служебные слои обновления. Он должен реализовать
протокол выше в пространстве; вызов Python-компилятора не считается
гостевой компиляцией. Реализация гостевого компоновщика относится к этапу 10.

## Проверки и стоимость

`make check-direct` проверяет 64 сценария и сравнивает данные и логические поля по карте с независимым
символическим эталоном; байты кода разных ABI не сравниваются. Есть случайные
слои, частичные поля и переносы, NOP, новый/заменённый слой, собственный патч,
чтение поля, косвенный переход, все устройства, SYS old/new/error/seek,
настоящий бинарник emulator, сохранение, повторные запуски, snapshot/resume и
отказы для неподдерживаемых исходников. CLI проверяет запуск без исходника,
целостность, живой ввод и наследуемые fd3/fd4. Автономный distcheck отдельно
проверяет оба установленных запускателя и установленный SYS SDK.

`make benchmark-direct BENCH_REPEATS=2 BENCH_TICKS=4` сравнивает реальные
конечные нагрузки с C-vm2 и интерпретатором на emulator. Измеряются отдельно
трансляция, запуск, загрузка, физические такты, размеры, RSS, редкие и частые
патчи. Контрольный упаковщик независим; его отдельный fetch-слой явно
оплачивает конфликт патч/чтение следующего слоя. Короткие серии включают
стоимость процесса, поэтому они не доказывают установившуюся скорость цикла.
Сохранённые результаты и ограничения замеров — в
[measurements/vm2-direct/README.md](measurements/vm2-direct/README.md).
