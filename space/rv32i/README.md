# RV32I на копикоде

В монорепозитории результаты находятся в общем `../../build/`, пути Makefile
выбираются автоматически. Общие команды из корня: `make -j1`,
`./tools/run/forth`, `make -j1 check`. Примеры с локальными `build/` и `dist/`
ниже относятся к самостоятельному распакованному выпуску; в workspace
для Forth используйте общий запускатель. Каталог legacy/ не требуется.


Самостоятельный владелец генераторов RV32I, runtime C, примеров и эталонов,
выделенных из copy-space. Происхождение и исходные хеши — PROVENANCE.json,
лицензия Apache-2.0. Старые пути copy-space временно являются ссылками.

Основной путь: универсальная машина RV32I генерируется в символический
копикод vm2, затем сохраняется как псевдоинструкции emulator (`vm2-direct-v1`).
Генератор не декодирует гостевые машинные инструкции. Гостевые ветвления,
арифметика, память и ECALL исполняются в пространстве.

Зависимости: Python 3.11+, vm2, copycode и bitcopy emulator; задаются через
VM2_ROOT, COPYCODE_ROOT, EMULATOR_ROOT и EMULATOR. Старый эмулятор copy-space
не является зависимостью основного пути. RISC-V GCC задаётся RISCV_CC;
его подготовка не означает гостевого исполнения C-компилятора.

```sh
make                           # сохранённый пример build/example
./rv32i run build/example       # код завершения гостя: 42
./rv32i build program.bin -o /tmp/guest
./rv32i build-c examples/rv32i/smoke.c -o /tmp/c-guest
./rv32i run /tmp/c-guest
make check                     # эталон, фактические операнды, C и resume
make benchmark                 # три коротких процесса и стоимость загрузки
make distcheck                 # проверки вне исходных деревьев
```

make работает последовательно на одном CPU с nice=15, пределом адресного
пространства 768 МиБ на процесс и таймаутом 180 секунд. LIMIT_SECONDS и
LIMIT_MEMORY_MIB задают бюджет. Вложенные команды сохраняют общую группу
процессов для завершения по таймауту. Локальный кэш toolchain перенесён
без копирования; архив его не включает, `make clean` его сохраняет.
Команды и форматы — [doc/build.md](doc/build.md). Исходные rv32i*.md
описывают также legacy-контейнер; адреса прямого пути берутся из map.json.

## Границы переноса

Legacy API в modules/rv32i*.py и scripts/rv32i/legacy_*.py сохранён для
copy-c/GCC до следующих этапов. pForth использует прямой backend
в самостоятельном ../pforth. Тесты с прежними именами test_rv32i*.py
сохранены как исходные legacy-проверки; они не входят в самостоятельный
набор прямого ABI. Непубличные тестовые инструменты copy-space не входят
в новый путь. Старые адреса гостевой памяти не меняются, физическое
размещение контейнера пересчитывает vm2.
Строгий src/src явно оплачивает размножение сигналов. Старый 256-слотовый
BulkImage теперь требует большего контейнера: профиль 8 МиБ отклоняется;
базовый профиль структурно проверяется с Layout 128 МиБ. Это не размер прямого образа.
Оставшиеся потребители copy-c/GCC должны перейти на прямой backend на своих этапах
либо явно пересобрать legacy с достаточным размером. Скрытого fallback нет.

## Расписание прямого пути

Данные, таблицы, поля и переходы типизированы. Независимые исходные
копирования группирует общий copycode.vm1.schedule.plan с бюджетом 7
операций на слой. RAW/WAR/WAW, src/src и задержки patch/fetch сохранены;
динамические операции и каналы служат границами. Последовательный контроль
доступен через compile_image(..., packing=False).
Выровненные таблицы имеют запас между записями, чтобы выбранные адресные
биты можно было переносить в обе границы без сумматора. Общую арифметику
обновления границ и монитор снимков предоставляет vm2/copycode.
Проверка назначения старого BulkImage не считается доказательством:
приёмка проверяет фактические операнды каждого такта готового emulator.

## Состояние и устройства

Регистры x0..x31, PC, статус и код завершения сохраняют 32-битный формат.
Гостевые инструкции и память — little endian. Карта размещения задаёт
физические адреса. SYS имеет ширины целевого emulator; старые IN/OUT-записи
не переносятся побайтно. ECALL 63/64/93 — read/write/exit, ошибки -38/-9/-14/-5.
Нулевой размер не обращается к каналу. SYS-ответ читается после границы
запроса. Кадры контроля идут в debug, пользовательский вывод — stdout.
Снимок на границе commit использует checkpoint прямого vm2. Внешние файлы
и их позиции восстанавливает вызывающая сторона.
`--checkpoint-every N` останавливается после N обычных commit; run возвращает
75, `--snapshot FILE` сохраняет продолжение. Счётчики commit и позиций IO —
uint32 modulo 2^32. Завершение и исключения не являются обычным commit.
После resume внешнему вводу передаётся остаток после сохранённого input_bytes.
