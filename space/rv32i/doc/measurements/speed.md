# Стоимость инструкции RV32I, 2026-10-20

Замер: `python3 -B tools/instruction_ticks.py -o doc/measurements/instruction-ticks.json`.
Каждый класс — 64 одинаковые инструкции и EBREAK; стоимость одиночного
EBREAK вычитается. Исполняет checked-emulator, который проверяет операнды
каждого такта; число тактов не зависит от нагрузки CPU. Регистры:
x1=0x12345678, x2=0x0f0f0f0f, x5=4096.

## Куда уходили такты

Профиль путей (адрес исполняемого слоя на каждом такте) показал, что почти
всё время занимала служебная работа патчей кода, а не вычисления:

- запись результата патчила полный адрес назначения: общий путь
  классификации каналов и сумматоров, 268 тактов на каждую инструкцию;
- верхняя граница патченного копирования (чтение регистров, выборка
  инструкции, загрузки) считалась 27-битным сумматором — около 45 тактов;
- косвенный переход (dispatch, branch, guard) складывал адрес слоя
  с размером слоя — около 45 тактов на каждый;
- обновление среза занимало 4 физических такта, а планировщик вставлял
  ещё пустой слой задержки старого физического ABI;
- сложение шло по одному разряду (32 зависимых чтения таблицы), OR-проверки
  тоже; сдвиг — 160 мультиплексоров; знаковое расширение и нулевые биты
  копировались из одного источника и поэтому шли по одному за такт.

## Изменения

- RV32I: тетрадный сумматор (8 шагов), OR до 8 входов, проверки кодировок
  по 7 бит, булевы операции по 4 разряда, сдвиг одним копированием из
  64-битного окна, знаковое расширение одной таблицей, запись регистра
  пятибитным срезом с отменой записи в x0.
- vm2: срез пишется прямо в нижнюю границу, затем один такт переносит его
  в верхнюю и в логическое поле; верхняя граница коротких срезов — таблица,
  для длины 2^j — префиксный инкремент; выровненные начала слоёв для
  косвенных переходов.
- copycode: задержка патча `fetch_delay=1` для прямого ABI, объединение
  соседних входных битов таблиц ассемблера в одну строку копирования.

## pForth

Полный запуск `./pforth run` от снимка после инициализации, один процесс,
время процесса:

| Ввод | До | После |
|---|---:|---:|
| `bye` | 0,68 с | 0,20 с |
| `: l 1000 0 do loop ; l bye` | 15,2 с | 2,2 с |
| `: l 10000 0 do loop ; l bye` | 114,2 с | 15,7 с |
| `: l 1000 begin 1- dup 0= until drop ; l bye` | 38,9 с | 5,2 с |
| `1 2 + . 3 4 + . 5 6 + . 7 8 + . 9 9 + . bye` | 6,0 с | 0,9 с |

Одна итерация пустого `DO LOOP` — около 1,6 мс вместо 11 мс. Emulator
исполняет около 3 млн тактов в секунду; теперь основная часть цикла
выборки — цепочка зависимых чтений таблиц по 4 такта каждое.
