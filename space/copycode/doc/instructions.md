# Кодирование и декодирование четырёхиндексной инструкции на Forth

[forth/instructions.fth](../forth/instructions.fth) использует
[битовый кодек](bitfields.md) и записывает четыре поля `dl, dh, sl, sh`
в том же формате, что `Format.layer` из `copycode.vm1.machine`.
Лицензия MIT, исполнение — внутри пространства на 32-битном pForth.

Слово `cc-instruction!` имеет стек:

```forth
( row buffer bytes bit address-bits -- )
```

`cc-instruction@` имеет тот же стек и читает четыре индекса из `buffer`
в массив `row`. Он возвращает все поля как двойные числа, включая нулевые
старшие ячейки. Проверка границ и раздельности буферов выполняется до записи
первой ячейки результата; входной образ не изменяется.

`row` указывает на восемь ячеек Forth: четыре беззнаковых двойных числа,
каждое в порядке младшая/старшая ячейка. Порядок чисел — `dl, dh, sl, sh`.
`buffer` — адрес байтового буфера, `bytes` — его объявленный размер,
`bit` — смещение инструкции внутри буфера в битах. Ширина каждого индекса
`address-bits` — от 1 до 64. Полная инструкция занимает `4 * address-bits`
бит; байтового выравнивания не требуется. Остальные биты буфера сохраняются.

Вызывающая программа предоставляет действительные выделенные области:
32 байта для `row` и `bytes` байт для результата. Области должны быть
раздельными; пересечение проверяется по всему объявленному буферу результата.
Границы, ширина и все четыре значения проверяются до первой записи.
`THROW -9` означает ошибку границ или пересечение буферов;
`THROW -24` — недопустимую ширину либо переполнение индекса.
Модуль не использует глобальные рабочие переменные и не выделяет память.

Это кодирование чисел. Проверка допустимости операции копирования,
каналов/SYS, непересечения операндов и совместимости инструкций одного
слоя остаётся отдельной задачей. Генераторы Python пока используют свой
кодек; Forth-модуль доступен следующим переносимым компонентам.

Из корня проекта загрузить оба исходника и затем вводить команды:

```sh
cat space/copycode/forth/bitfields.fth space/copycode/forth/instructions.fth - | ./tools/run/forth
```

Пример для четырёх 16-битных индексов:

```forth
create row 8 cells allot
row 8 cells 0 fill
800 row ! 808 row 2 cells + !
1024 row 4 cells + ! 1032 row 6 cells + !
create code 8 allot
code 8 0 fill
row code 8 0 16 cc-instruction!
code 8 0 16 cc-field@ swap . . cr
bye
```

Первое поле прочитается как `800 0`.

Проверка: `make -C space/forth -j1 check-instructions`.
Независимый Python-эталон задаёт ожидаемые байты, Forth-код выполняет
запись в пространстве. Проверяются настоящий 27-битный ABI, ширина 1,
невыровненный старт, последний допустимый бит, сохранение соседних битов,
переполнение последнего индекса до начала записи, ошибки границ и ширины,
пересечение буферов и пустой стек. Данные проверки находятся в
`build/space/forth/build/verification/instructions/`.
Предел — `INSTRUCTION_SECONDS` (600 секунд), один CPU, nice=15, 768 МиБ.
Приёмка пройдена: 2 корректных сценария и 8 ошибочных, полное совпадение
байтов и вывода с Python-эталоном, глубина стека — 0.

Декодер проверяется отдельно: `make -C space/forth -j1 check-instruction-decode`.
Входные байты формирует Python независимо от Forth-кодировщика: 27-битная
инструкция с невыровненным началом, ошибки границ/ширины/пересечения буферов,
сохранность входа и результата при ошибках, пустой стек.
