# Бэкенд индексного кода на Forth

[forth/backend.fth](../forth/backend.fth) строит слои псевдоинструкций emulator
и выдаёт загрузочный поток в stdout. Хостовый контроль — `copycode.vm1.backend`;
обе реализации обязаны давать одинаковые байты. Лицензия MIT, исполнение внутри
пространства на 32-битном pForth. Пункт роадмапа 9.4.5.

## Машина и раскладка

`cc-machine ( size slots cell-bits chunk-bytes -- )` задаёт emulator `-s size -p slots`.
Ширина адреса a — разрядность size; она должна быть кратна 8, чтобы поля
инструкции были байтовыми. Поддерживается slots = 8 (этого требует загрузчик).
Ячейка — степень двух бит не меньше слоя; ячейка 0 — входной слой процессора.
Повторный вызов освобождает прежние буферы.

Слой содержит slots-1 рабочих строк и строку ссылки в последнем слоте, которая
загружает следующий слой в процессор. Строка — четыре поля `dl dh sl sh`.

## Ячейки, ссылки и группы

- `cc-builder ( first-cell -- )` — номер первой свободной ячейки (обычно 2:
  ячейка 1 остаётся нулевой и служит остановом).
- `cc-new-cell ( -- addr )` — адрес следующей ячейки. Адрес выдаётся при
  создании слоя, поэтому прямая ссылка — это адрес ячейки, заполняемой позже
  (`cc-lone`); отдельной таблицы меток и последующих релокаций не нужно.
- `cc-group ( k -- base )` — 2^k ячеек, выровненных на 2^k ячеек: срез битов
  поля ссылки выбирает одну из них.
- `cc-seq ( first|-1 -- )` начинает последовательность; `cc-layer ( -- layer )`
  создаёт слой (первый — в first, если задан) и связывает с ним предыдущий;
  `cc-jump ( target -- )` задаёт продолжение последнего слоя, `cc-entry`,
  `cc-last`, `cc-seq@ ( i -- layer )` дают доступ к слоям последовательности.
- `cc-lone ( -- layer )` — отдельный слой в новой ячейке; `cc-next! ( target layer -- )`.
- `cc-row ( dl dh sl sh layer -- slot )` добавляет строку; пересечение с уже
  добавленными операндами памяти (включая src/src) отклоняется.
- `cc-copy ( n dst src -- row )`, `cc-out ( n src -- row )` (stdout),
  `cc-field ( cell slot f -- addr )` — адрес поля f (0..3) строки слота.

`cc-flush` кодирует ожидающие слои в порядке создания и передаёт их в поток;
после него записи слоёв переиспользуются, последовательность заканчивается.
Одновременно ожидают до 96 слоёв.

## Поток

- `cc-put ( bit-address src n -- )` и `cc-put-numeric ( value nbytes bit-address -- )`
  записывают байты образа. Соседние записи с зазором до 32 байт объединяются
  в кусок до chunk-bytes; большие записи делятся. Каждый кусок — слой-загрузчик
  и данные.
- `cc-finish ( entry -- )` закрывает поток входным слоем, ссылающимся на entry.

Образ выдаётся по мере построения; всё пространство в памяти гостя не хранится.
Числовые поля записываются младшим битом вперёд в порядке позиций, байт
потока — старшим битом вперёд (контракт emulator).

## Ошибки

`THROW -24` — недопустимая машина, переполнение поля, слой без продолжения;
`-9` — пересечение операндов в слое или запись вне загружаемого пространства;
`-8` — переполнение слоя или пула слоёв.

## Проверка

`space/forth/tests/test_backend.py`: гость строит программу с прямой ссылкой,
группой, объединёнными и разделёнными кусками; поток побайтово совпадает
с хостовой моделью и исполняется на checked-emulator с ожидаемым выводом.
Восемь ошибочных вызовов возвращают ожидаемые коды. Хостовая модель также
используется транслятором RV32I (`space/rv32i/modules/translate.py`).
