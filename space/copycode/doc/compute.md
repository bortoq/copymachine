# Вычисления копированиями на Forth

[forth/compute.fth](../forth/compute.fth) — библиотека поверх [бэкенда](backend.md):
вычисления, зависящие от данных, выполняются чтением таблиц, адрес которых
патчат копирования. Хостовый контроль — `copycode.vm1.compute`; потоки обеих
реализаций совпадают побайтно. Лицензия MIT. Пункт роадмапа 9.4.6.

## Чтение таблицы

Запись таблицы занимает 2^s бит при ширине меньше 2^s, поэтому биты индекса
одинаковы в нижней и верхней границе источника. Индексные биты копируются
в обе границы строки чтения: все нижние патчи, затем все верхние (один
источник нельзя читать дважды в такте), один пустой слой, затем чтения.
Два чтения одной таблицы не ставятся в один слой: при равных индексах у них
был бы общий источник.

- `cc-lookups-begin`, `cc-item ( table s width out preset -- )`,
  `cc-seg ( src n index-offset -- )` (до 4 сегментов), `cc-lookups`.
- `cc-tables ( at limit -- )`, `cc-table ( xt bits s -- base )`: таблица из
  2^bits записей, значение записи i — `xt ( i -- v )`; выравнивание на размер.
  `cc-table2 ( xt bits s -- base )` — то же для записей шире ячейки
  (s ≥ 6): `xt ( i -- lo hi )`, младшие 32 бита первыми. Это нужно гостю
  с 32-битными ячейками. `cc-table-area ( bits s -- buf )` и
  `cc-table-done ( -- base )` дают буфер таблицы для прямого заполнения:
  запись i лежит с байта i·2^s/8.
- `cc-standard-tables`: `cc-t-add`, `cc-t-sub` (тетрадный сумматор и
  вычитатель, 512 записей: сумма, перенос, копия переноса), `cc-t-xor/or/and`
  (тетради), `cc-t-or8`, `cc-t-flags` (EQ, NE, LT, GE, LTU, GEU парами),
  `cc-t-not5`, `cc-t-sign32`, `cc-t-fill24`, `cc-t-fill16`, `cc-t-inc1/2`.

## Блоки

- `cc-adder ( table x a b carry -- )`: x = a + b или a + ~b + 1 за 8 связанных
  тетрадных шагов, 25 слоёв; x — 34 бита, перенос и его копия в x+32.
- `cc-logic ( table res a b -- )`: 8 тетрадных чтений.
- `cc-shift-right ( res a amount w zero arithmetic -- )`,
  `cc-shift-left ( res a amount w zero u -- )`: одно копирование 32 бит из
  64-битного окна w (выравнено на 64); величина amount[0:5] патчит источник.
- `cc-or-chunks ( out src lo hi -- )`: элементы OR по 8 бит для проверок
  диапазона/выравнивания адреса.
- `cc-compare ( res a b z flags -- )`: после вычитателя — флаги сравнения.
- `cc-decide ( src k -- group )`: продолжение в ячейке группы с номером
  src[0:k]; src[k:2k] — копия значения.
- `cc-flag-exit ( c2 flags -- row exit )`: пара флагов, выбранная патчем
  источника строки row, становится битом номера ячейки в ссылке выхода:
  возврат в ret или ret+ячейка.
- `cc-exit-layers ( res discard width -- xw x )`: общие выходы обработчиков
  с патчем места результата и ссылки; `cc-call-rows ( exit lo hi layer -- )` —
  строки места вызова, записывающие адрес возврата.
- `cc-halt-begin`, `cc-halt-region ( n src -- )`, `cc-halt-end ( -- cell )`:
  выдача областей в stdout и останов; `cc-stub ( status constant halt -- )`.

Слова хранят состояние в переменных и не реентерабельны. `THROW -8` —
переполнение списка элементов, сегментов или области таблиц.

## Проверка

`space/forth/tests/test_compute.py`: программа с общим обработчиком сложения,
вызванным из двух мест, вычитанием, сравнением, XOR, тремя сдвигами, выбором
возврата по флагу, многоходовым ветвлением, заглушкой и остановом. Поток
гостя совпадает с хостовой моделью; на checked-emulator все десять
результатов совпадают с вычисленными на хосте. Модель транслятора RV32I
использует те же блоки; её поток не изменился побайтно.
