# Проверка и доказательство (14.12)

Доказательство — полная проверка слова. Слова языка `check-table` и `accuracy` проверяют слово
таблицей, `proved?` спрашивает, доказано ли оно. Доказанное слово ссылается на общее слово
«доказано» (таблицу из одного однобитного значения 1).

## Слова

| Слово | Что делает |
|---|---|
| check-table ( xt in-bits out-bits table -- ok ) | исполняет слово xt на всех 2^in-bits наборах и сравнивает с таблицей; ok — -1, если совпали все наборы, иначе 0 |
| accuracy ( xt -- n ) | доля совпавших наборов в миллионных (1000000 — все); для слова, которое не проверяли, 0 |
| proved? ( xt -- f ) | -1, если последняя проверка слова совпала полностью |

- **Набор** — одно число на стеке, `i` от 0 до 2^in-bits − 1. Слово xt ( i -- r ) берёт его и оставляет
  результат. Таблица — массив ячеек (`create t 16 allot`): ячейка `i` — ожидаемый результат для набора
  `i`. Сравниваются младшие out-bits бит результата и ячейки.
- **Допустимые аргументы:** in-bits от 0 до 31, out-bits от 1 до 32. Иначе ничего не исполняется:
  ok 0, проверено 0 наборов.
- **Полная проверка делает слово доказанным.** Запись слова в реестре программы получает ссылку на
  `%proved` — копию общего слова «доказано» в памяти программы (у недоказанного ссылка 0).
  Последняя проверка решает: слово, которое потом не прошло проверку другой таблицей или с
  недопустимыми аргументами, снова не доказано.
- **accuracy** считает совпавшие наборы по последней проверке. Чтобы произведение с 1000000 не
  вышло за 32 бита, число совпавших наборов сдвигается вправо на max(0, in-bits − 11), а число наборов
  берётся 2^min(in-bits, 11); для in-bits до 11 результат точен (целая часть), для больших округлён
  вниз, но равен 1000000 только при полном совпадении.

Примеры (`tests/test_proof.py`):

| Проверка | Результат |
|---|---|
| and, or, xor на 1 бит (вход: бит 0 — a, бит 1 — b) | ok -1, `proved?` -1, `accuracy` 1000000 |
| сложение 4 бит двумя определениями (сдвиги и `+`; полусумматоры в цикле) | таблицы, снятые исполнением, равны; оба доказаны таблицей суммы |
| сложение, испорченное на сумме 17 (14 из 256 наборов) | ok 0, `proved?` 0, `accuracy` 945312 |
| недопустимые in-bits 32, out-bits 0 и 33 | ok 0, `accuracy` 0 |
| слово, испорченное на одном из 4096 наборов | ok 0, `accuracy` 999511 (сдвиг до 11 бит) |

## Где хранится доказательство

Проверка идёт при исполнении программы, а запись словаря компилятора живёт при компиляции:
поэтому результат хранит **реестр доказательств в памяти программы**, а не запись `fc-wt`. Его
слова написаны на языке и подключаются к программе, когда её текст называет `check-table` или
`accuracy` (`fc-scan-uses`: нужда 16 у регистрации; `fc-library`):

- `%e` — 32 записи по 8 ячеек, `%n` — сколько занято; запись слова ищет по xt `%slot` (линейно; новая
  запись — нули; 33-е слово — `-8 throw`). Ячейки записи: 0 xt, 1 число совпавших наборов, 2 их биты
  (in-bits; 0 у недопустимых аргументов), 3 способ (1 — таблица, 0 — ничего), 4 доказательство
  (адрес `%proved` или 0); с 14.13 ещё 5 out-bits и 6 таблица последней проверки — эталонные
  артефакты понятия для `replace` (`doc/replace.md`).
- `%proved` — 4 байта со значением 1: общее слово «доказано» в памяти программы (копия `fc-proved`).
- `%check`, `%acc`, `%prv` — определения; под именами `check-table`, `accuracy`, `proved?` они
  становятся синонимами (`fc-synonym`: запись словаря с той же ячейкой понятия, определением и
  ценой; 14.13). Записи
  новее генераторов этих имён и перекрывают их. Остальные имена с `%` — внутренние переменные.

Имена с `%` — внутренние слова реестра. Программа их видит (они в её словаре) и может переписать
ячейки реестра; защиты от этого нет.

Запись компилятора (`fc-wt`, ячейка 14) не меняется: `fc-unproved` — «при компиляции ничего не
проверено», `fc-proved` ставит только проба `prove!` из тестов 14.11. Генератор `proved?` 14.11
(литерал по записи компилятора) остаётся для программ, которые не называют `check-table` и
`accuracy`: в них `proved?` — по-прежнему литерал, с `check-table` и `accuracy` — слово реестра.

## Решения исполнителя (автор может изменить)

1. **Проверка при исполнении, доказательство в реестре программы, а не в записи компилятора.**
   Компилятор не исполняет код слов, поэтому при компиляции он ничего проверить не может.
2. **Слова доказательства — слова на языке, а не генераторы.** xt берётся со стека при исполнении
   (`execute`), так что проверять можно слово, которое выбрано во время исполнения. Генератор,
   которому xt нужен как литерал при компиляции, был бы дороже: первая версия (xt-литерал в
   четвёртом элементе кэша, текст кода, вписываемый генератором) увеличивала L0 на 658 КБ.
3. **L0 теперь 16 671 398 байт при пределе 16 МиБ = 16 777 216** (`limited_run.py`: размер файла
   ограничен 16 МиБ по умолчанию, и проверка пункта идёт под этим пределом): остаётся 105 818 байт,
   около 830 ячеек кода. Следующие пункты будут упираться в предел; решать автору (поднять
   `--file-mib`, сжимать L0 или уменьшать определение).
4. **Имена `check-table`, `accuracy`, `proved?` связаны не определением `:`, а `fc-synonym`.**
   Определение `: check-table` в тексте определения языка заметил бы просмотр `fc-scan-uses`
   (он видит слова и внутри строк `s"`) и подключил бы слова доказательства к самому ядру (+2200
   ячеек, +280 КБ).
5. **Сравниваются младшие out-bits бит**, а не весь результат; оба — результат слова и ячейка
   таблицы. Недопустимые аргументы не исполняют слово и считаются непроверенными.
6. **Последняя проверка решает** (запись перезаписывается): неудачная проверка снимает прежнее
   доказательство.
7. **accuracy — доля совпавших наборов**, а не доля исполненных: иначе у испорченного слова она
   была бы 1000000.
8. **Реестр на 32 слова**, линейный поиск; общий для программы счётчик `%n`.
9. **Хост pForth: свободное место словаря кода 64 КиБ кончилось** (после 14.11 оставалось 1688
   байт, при 14.12 — 856 при минимальном варианте; за пределом pForth падает без сообщения).
   `tools/host.py` берёт копию образа словаря `pfdicdat.h` с большим свободным местом (имена +64 КиБ,
   код +256 КиБ); образ в `space/forth` и гость не менялись.

## Что не закрыто, и замеченное

- Проверка таблицей — только полная (все 2^in-bits наборов); частичной проверки (выборкой) нет, хотя
  `accuracy` и запись «проверено / способ» её допускают.
- Слово xt получает набор одним числом; слова с несколькими входами (сложение 4 бит: a и b в одном
  числе) нужно обернуть, как `add4a` в тесте.
- Реестр не защищён от программы (изоляция 14.10 защищает ядро, не слова в самой программе).
- **Найдено, к пункту не относится:** `over execute` (xt, скопированный `over`/`dup` в регистр кэша)
  даёт на checked-emulator «AUDIT overlap: 0..1024 / 0..1024»; `2 pick execute` и xt из `@` — нет
  (проверено на программе без слов доказательства). Библиотека берёт xt через `@`.
- `fc-scan-uses` видит слова и внутри строк `s"` и просмотром комментариев `( )` (нужда комментария
  8 есть только у `\`).
