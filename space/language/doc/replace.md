# Замена определения и синонимы (14.13)

Слово языка `replace ( xt concept -- ok )` заменяет определение понятия concept определением слова
xt, если кандидат прошёл проверку рабочим словом проверки, его точность не ниже и цена меньше.
Синоним `: a b ;` — имя a на ячейку понятия b, без кода. Тест — `tests/test_replace.py`
(`make -C space/language check-replace`).

## Устройство

**Программа замены.** Программа, текст которой называет `replace`, — программа замены (потребность
32 у `fc-scan-uses`, вместе с 16 — словами доказательства 14.12). В ней у каждого слова есть
**ячейка понятия в коде**: группа из двух ячеек перед входом слова, в ней один слой, строка связи
которого ведёт на вход текущего определения (в программе ядра в слое ещё метка входа изоляции,
14.10). Содержимое ячейки понятия записи компилятора (ячейка 3) — адрес этой ячейки: туда идут
вызов слова, `[']` и `execute`, `recurse`. Замена — запись нового входа в строку связи (поля
источника sl, sh) словом `space!`; уже скомпилированные вызовы идут в новое определение.

В остальных программах (37 программ `check-programs`, определение языка) вызов через ячейку
понятия по-прежнему разрешается при компиляции (14.11): косвенного шага нет, потоки 37 программ
побайтно равны модели, L0 равен K0.

**Записи слов в памяти программы.** Проверка 14.12 идёт при исполнении, поэтому и замена — при
исполнении. Цену и определения слов программе даёт таблица %w: `gen-semicolon` пишет запись слова
в память программы вместе с потоком (`fc-concept-record`, `fc-poke`). Запись — 40 байт, ячейки 3,
6–13 и 15 записи компилятора: 0 ячейка понятия (xt), 4 8 12 определения индексного, копи- и хост
пространства, 16 размер, 20 биты, 24 копирования, 28 слои, 32 признак «известна при компиляции»,
36 стек определений. До 99 слов (далее -8 при компиляции); таблица кончается нулевой записью.

**Слова замены** написаны на языке и компилируются до программы (`fc-replacement`, как слова
доказательства `fc-library`):

| Слово | Что делает |
|---|---|
| replace ( xt concept -- ok ) | синоним %replace |
| cost ( xt -- size bits copies layers known ) | в программе замены — синоним %cost: цена **текущего** определения при исполнении; xt может быть вычислен при исполнении; не слово — 0 0 0 0 0 |
| %rec ( xt -- record\|0 ) | запись слова по ячейке понятия (линейный поиск) |
| %price ( xt -- n known ) | `price` записи и признак |
| %link ( def concept -- ) | пишет определение в строку связи ячейки понятия |

`replace`: ok -1 — заменено; иначе ничего не меняется и ok — причина:

0. xt или concept — не слово программы;
1. **артефакты**: у понятия нет эталонных артефактов (его не проверяли таблицей) или кандидат на них
   не прошёл. Эталонные артефакты понятия — таблица его последней проверки `check-table`: запись
   реестра доказательств теперь хранит и out-bits, и адрес таблицы (ячейки 5, 6). Кандидата
   проверяет %check — определение понятия check-table (check-table — синоним %check с той же
   ячейкой понятия), то есть рабочее слово проверки;
2. **точность**: `accuracy` кандидата ниже точности понятия;
3. **цена**: `price` кандидата не меньше цены текущего определения, или одна из цен не известна при
   компиляции («по исполнению»: цикл, рекурсия, вызов xt).

При успехе запись понятия (весь 40-байтный блок) копируется в узел стека определений %ds (до 32
узлов, иначе -8 при исполнении), ячейка 36 записи указывает на узел; в запись понятия идут
определения и цена кандидата; `%link` пишет вход определения кандидата в ячейку понятия; запись
реестра доказательств понятия получает число совпавших наборов и доказательство кандидата.
Прежнее определение не уничтожается: его вход в узле, его можно исполнить (тест).

Проверяется само понятие; зависимые слова (вызывающие его) — нет, до решения 2.2.7.

**Цена в программе замены** — путь от ячейки понятия: журнал слова начинается со слоя ячейки
понятия (`fc-concept`), поэтому цена включает этот шаг (+1 слой, +1 копирование, +1024 бита; в
программе ядра ещё метка: +1 копирование, +32 бита). Вызывающий получает цену вызова точно.
Сверка со счётчиками 13.4 (`tools/counters.py`): слои и биты исполнения равны цене, исполненные
инструкции — копированиям; после замены исполнение слова стоит цену кандидата.

**Синоним.** `gen-colon` смотрит вперёд (`fc-synonym?`): если за именем A идёт слово B (запись вида
1), а за ним `;`, то A — синоним (`fc-synonym-of`): запись без кода, ячейка 5 — указатель на
ячейку понятия B (у B-синонима — уже на ячейку первого слова цепочки), цена, определения,
доказательство и стек скопированы. Вызов A, `[']` A и cost A — те же, что у исходного, и следуют
за заменой. Синоним работает в любой программе (не только в программе замены); `fc-synonym` 14.12
(check-table, accuracy, proved?) теперь тоже делит ячейку понятия.

## Тест (`tests/test_replace.py`)

Сложение двух 4-битных чисел из одного 8-битного набора, артефакт — младшие 5 бит суммы (таблица
из 256 ячеек). Исходное определение `add` — 5 развёрнутых полусумматоров без цикла; кандидаты:
`add-fast` (`+`), `add-bad` (испорчено на сумме 17), `add-loop` (полусумматоры в цикле), `add-dear`
(`+ 1+ 1-`). Цена `price` (сумма размера, бит, копирований, слоёв): add 314 102, add-fast 90 697,
add-dear 144 655.

| Шаг | ok |
|---|---|
| add-bad вместо add | 1 (артефакты; он дешевле add) |
| add-loop вместо add | 3 (цена по исполнению) |
| add-fast вместо add | -1 |
| add-dear вместо add (теперь add-fast) | 3 |
| add-fast ещё раз | 3 (цена не меньше) |
| понятие `c.`, не проверенное таблицей | 1 |
| 5 вместо add, add вместо 5 | 0 |

- Цепочка `: s1 add ; : s2 s1 ; : s3 s2 ;` исполняет текущее определение: определения совпадают на
  8-битных наборах и различаются вне их (у исходного старший полубайт не маскируется): `256 s3` —
  16 до замены и 0 после; так же s2, s1, add и `['] s3 execute`. `['] s3` равен `['] add`.
- `cost` s3 равен `cost` add: до замены — цене add, после — цене add-fast.
- Стек определений: один узел, в нём прежнее определение; `256` через него — 16.
- После замены add доказан, точность 1000000.
- Без `replace`: синонимы не делают кода — поток программы с s1 s2 s3 побайтно равен потоку той же
  программы, вызывающей add; `cost` синонима при компиляции равен `cost` add; `: s4 ( комментарий )
  add ;` — обычное определение.
- Ядро L0 на emulator компилирует и исполняет программу замены: тот же вывод, цены с двумя метками
  входа на слово (ячейка понятия и вход).

## Цифры

- L0: 16 671 398 → **16 967 309** байт (+295 911, +1,8 %): `fc-synonym?`, `fc-synonym-of`,
  `fc-concept`, `fc-concept-record`, `fc-poke`, `fc-concepts`, `fc-replacement` (текст слов
  замены) и правка `gen-colon`, `gen-semicolon`, `fc-library`. L0 больше 16 МиБ (16 777 216) на
  190 093 байта: под пределом `limited_run.py` по умолчанию бут не пишет L0, нужен `--file-mib`
  больше 16 (проверка пункта идёт с 64). Первая версия давала +395 887; компилятор дорог на
  каждую операцию (около 10 ячеек по 128 байт), поэтому логика замены — в тексте слов на языке,
  а не в словах компилятора.
- `check-programs STREAMS=equal`: 37 программ, потоки равны модели. L0 = K0 (`test_boot.py`).
  `external 0`. Ядро — 866 слов (было 856), записи в `doc/language.md` — на все.
- Программа замены теста на хосте и checked-emulator — секунды; ядро L0 — около 225 с (511 с при
  параллельной нагрузке). Вся проверка пункта — 1012 с.

## Решения исполнителя (автор может изменить)

1. **Косвенный вызов только в программе замены.** В 14.11 вызов через ячейку понятия разрешается
   при компиляции, а проверка 14.12 и, значит, замена — при исполнении. Косвенный шаг для всех
   программ изменил бы потоки 37 программ и L0; поэтому ячейка понятия в коде есть только у слов
   программы, которая называет `replace` (у всех её слов, а не только у участвующих в замене:
   заменяемым может оказаться любое слово, и xt любого слова — ячейка понятия). Цена шага — один
   слой на вызов. Другие способы (перекомпиляция зависимых, перепатч мест вызова) не делались.
2. **xt слова в программе замены — его ячейка понятия**, а в ячейку понятия пишется **определение**
   кандидата (вход из его записи), а не его ячейка понятия: понятие не начинает следовать за
   будущими заменами кандидата.
3. **Эталонные артефакты понятия — таблица его последней проверки `check-table`** (in-bits, out-bits,
   таблица в реестре 14.12). Отдельного слова «артефакты» нет; непроверенное понятие заменить
   нельзя (причина 1).
4. **Рабочее слово проверки — %check по его ячейке понятия.** Текст слов замены не может назвать
   check-table: просмотр `fc-scan-uses` видит слова и внутри строк `s"` и подключил бы слова
   доказательства и замены к самому ядру. %check и check-table — одно понятие (одна ячейка
   понятия), так что замена check-table повлияла бы и на `replace`.
5. **Ветка «точность» сейчас недостижима:** проверка таблицей полная, прошедший кандидат имеет
   точность 1000000. Ветка оставлена для частичных проверок и заменённого слова проверки.
6. **Цена должна быть известна при компиляции у обоих**; равная цена — отказ. Сравнивается число
   `price` (генератор: сумма), формула — в одном месте.
7. **После замены доказательство понятия — доказательство кандидата** (число совпавших наборов и
   ссылка на «доказано» переносятся в запись реестра понятия).
8. **Строка связи ячейки понятия пишется двумя `space!`** (поле sl, затем sh = sl + 1024). Это не
   одна запись на границе такта, как в 2.1.3, но между ними ячейка понятия не исполняется: её
   пишет исполняющийся `replace`.
9. **Синоним — только точный текст `: a b ;`**, b — слово (не генератор и не данные). Комментарий в
   теле делает обычное определение: в определении языка есть `: gen-kernel-layout ( -- )
   fc-top-only ;`, и синоним из него изменил бы L0 (L0 перестал бы равняться K0 модели). В 37
   программах и в определении языка точного `: a b ;` нет (проверено разбором текста).
10. **Синоним — во всех программах**, не только в программе замены: потоков 37 программ это не меняет.
    Ячейка 3 записи синонима — 0 (не используется: всё идёт через ячейку 5).
11. **Таблица слов программы — память программы, заполненная потоком** (как строки `s"`); её и стек
    определений программа может переписать, защиты нет (как у реестра 14.12).
12. **cost в программе замены — слово при исполнении** (цена текущего определения), в остальных
    программах — генератор 14.11 (литерал по записи компилятора).
13. **Находка 14.12 (`over execute`, `dup execute` → AUDIT overlap)**: шаблон не понадобился (xt
    берётся через `@`, в тесте — `swap execute`); в девяти простых вариантах (`dup execute`, `over
    execute` в цикле и вне, с памятью) ошибка не воспроизвелась, причина не найдена, не исправлялось.
14. `test_replace.py` — отдельная цель `check-replace`, не в `check` (ядро L0 — 4–9 минут).

## Что не закрыто

- Зависимые понятия не проверяются (2.2.7); цена вызывающего слова в его записи посчитана при
  компиляции с ценой прежнего определения и после замены не пересчитывается.
- Замена — только в программе; слова ядра L0 не заменяемы (их вызовы связаны при компиляции).
- Нет слова возврата к прежнему определению из стека определений (узел только хранится).
- Ветка «точность» не проверена тестом (недостижима при полной проверке таблицей).
- Цена «по исполнению» не сравнивается: кандидат с циклом не может заменить слово.
- L0 больше 16 МиБ.
