# pForth на emulator

В монорепозитории результаты находятся в общем `../../build/`, пути Makefile
выбираются автоматически. Общие команды из корня: `make -j1`,
`./tools/run/forth`, `make -j1 check`. Примеры с локальными `build/` и `dist/`
ниже относятся к самостоятельному распакованному выпуску; в workspace
для Forth используйте общий запускатель. Каталог legacy/ не требуется.


Самостоятельный порт pForth 2.2.0, upstream
`e5617638c3a397c644fe82c6301711867a0ca1bf`. C-ядро собирается в RV32I,
универсальная RV32I-машина — в четырёхиндексные инструкции emulator.
Пользовательский Forth исполняется в пространстве; хост не разбирает задания.

Зависимости: Python 3.11+, C-компилятор, RISC-V GCC и проекты rv32i,
vm2, copycode, emulator. Пути задаются RV32I_ROOT, VM2_ROOT, COPYCODE_ROOT,
EMULATOR_ROOT; по умолчанию это соседние каталоги. RISCV_CC выбирает GCC.

```sh
make -j1
printf '1 2 + . cr bye\n' | ./pforth run build/pforth
./pforth job build/pforth examples/pforth/demo.fth -o build/demo-job
./pforth run-job build/demo-job
make check
make benchmark                 # linear/indexed и serial/packed, один CPU
make prepare-check
```

Сборка, каждый тест и подготовка словаря ограничены одним CPU, nice=15,
768 МиБ адресного пространства. Сборка ограничена 180 секундами,
отдельная языковая сессия — 360 секундами (TEST_SECONDS). make выполняется последовательно.
LIMIT_SECONDS и LIMIT_MEMORY_MIB задают пределы.
Расширенная языковая проверка разделена на отдельные сессии, чтобы каждая
укладывалась в заданный предел. Прямой запуск CLI подчиняется
ограничениям вызывающей стороны; для него можно применять
`python3 ../vm2/tools/limited_run.py --seconds 180 --memory-mib 768 ./pforth …`.

Гостевая память — 512 КиБ. Словарь, стек и определяемые слова остаются
в гостевой памяти. Поддерживаются целочисленные вычисления, определения,
условия, циклы, переменные и строки. Файловая система и float отключены.

Общая библиотека [битовых полей](../copycode/doc/bitfields.md) написана
на Forth и проверяется внутри пространства: `make -j1 check-bitfields`.
Эта проверка ограничена 600 секундами (`BITFIELD_SECONDS`); полный `distcheck`
— 900 секундами (`RELEASE_SECONDS`). Ограничения CPU и памяти сохраняются.
Кодировщик четырёхиндексной инструкции проверяется отдельно командой
`make -j1 check-instructions` (600 секунд, `INSTRUCTION_SECONDS`), а также
в обычном `check` и проверке самостоятельного выпуска.

Проверки сохраняют вход, stdout/stderr, команды и снимки в
build/verification. Холодная инициализация выполняется один раз внутри emulator;
дальнейшие тесты используют сохранённое продолжение до первого read.
Обычный build/pforth запускает инициализацию заново. Детали, ABI задания,
API подготовки словаря для copy-c и ограничение i386 — [doc/build.md](doc/build.md).
Upstream имеет лицензию ISC (LICENSE и third_party/pforth/license.txt),
извлечённый порт — Apache-2.0 (LICENSE.port). Происхождение — PROVENANCE.json.

Поиск имён использует гостевой индекс с 4096 корзинами; встроенный словарь
содержит 381 имя, пользовательские определения добавляются в индекс внутри
RV32I. Проверены переопределения, регистр, IMMEDIATE/SMUDGE, изменение
заголовков и CONTEXT. build --linear-search и --serial-rv32i выбирают
контрольные варианты. RV32I группирует независимые копирования общим
планировщиком copycode; динамические операции и каналы остаются границами.
Парные результаты ускорения — doc/measurements/optimization/.
