# Самостоятельный pForth

Этап 8: физический владелец порта, upstream, словаря и подготовки — pforth.
Основной backend — публичный rv32i.modules.direct_target.compile_image;
RV32I не копируется. Зависимость RV32I_ROOT задаёт дерево rv32i, которое
само объявляет emulator/vm2/copycode. Гость имеет 512 КиБ, стек начинается
за 16 байт до конца памяти. ECALL read/write/exit совпадают с runtime rv32i.

Пользовательский Forth читается из stdin и исполняется внутри emulator.
Задание — каталог с сохранённым прямым образом и task.fth; JSON содержит
SHA256 обоих компонентов. run-job проверяет их и передаёт исходный текст
гостю без разбора Forth на хосте. Вывод — stdout, код завершения — код гостя.
Старый IN-контейнер сохраняется только в legacy_build.py для перехода copy-c.

API scripts/pforth/prepare.py: prepare(output, additions=(), extra_cflags=(),
artifacts=None, headers_reserve=32768, code_reserve=65536). Это подготовка
32-битного словаря при сборке, а не исполнение пользовательского задания.
Сохранены точная upstream-ревизия и хеши словаря; --prepare-check повторяет
подготовку во временном каталоге и сравнивает заголовок и метаданные.

Проверки один раз исполняют холодную инициализацию в настоящем emulator и
сохраняют всё пространство непосредственно перед первым вызовом cs_read.
Тесты продолжают это состояние через публичный vm2 artifact.resume:
так определения и диагностические случаи не оплачивают инициализацию заново.
Обычный build/pforth остаётся холодным образом. Наблюдатель tests/observe_vm1.c
подключает исходный runtime/bitcopy/SYS emulator, записывает PC/статус каждую
миллионную физическую итерацию и конечный снимок. Он не декодирует RV32I
и не интерпретирует Forth. Пакет задания проверяется также обычным emulator.
Ошибка ввода проверяется заменой stdin на дескриптор каталога перед первым
cs_read в тестовом наблюдателе; чтение действительно завершается EISDIR.
Это проверочный адаптер устройства, не изменение гостевой программы.

Песочница данной среды запрещает системные вызовы i386: prepare-check
завершается явной ошибкой. Подготовка сохранена без изменения алгоритма,
проверка upstream/входного system.fth/заголовка/метаданных выполняется
без этого ограничения. Повторная генерация здесь пока не подтверждена.

Команды выпуска: make dist создаёт детерминированный исходный архив с
явными снимками зависимостей rv32i/vm2/copycode/emulator. make distcheck распаковывает
его вне исходных деревьев, собирает pForth, исполняет пакет задания на emulator,
проверяет идентичности и побайтную повторяемость архива. Toolchain в архив
не включается; задаётся RISCV_CC. make clean удаляет только build/dist.

Старые пути copy-space/runtime/pforth, third_party/pforth, examples/pforth,
doc/pforth.md и tests/test_pforth.py сохранены ссылками. scripts/pforth/build.py
в copy-space явно ссылается на legacy_build.py; основной build API находится
в pforth/scripts/pforth/build.py. make pforth/test-pforth/pforth-job в copy-space
передаёт работу новому владельцу. У copy-c добавлен собственный include path
для его заголовков; порт pForth больше не предполагает соседний runtime/copy_c.

Во время переноса выявлена стоимость побитного декодирования native emulator.
space_get в общем runtime теперь читает поле побайтно с обращением порядка
битов; формат и границы чтения сохранены. Тест runtime сравнивает результат
с независимым побитным эталоном для всех ширин 0..64 и допустимых смещений
в десяти байтах на 256 случайных буферах, включая самый конец буфера.
Это ускорение общего runtime используется также обычным emulator, не только тестами.

Тест test_pforth_legacy.py сохраняет прежнюю регрессию copy-space и требует
того дерева и его эмулятора. Он не входит в самостоятельный make check.
Приёмка этапа 8 использует tests/test_direct.py с новым native ABI.

Upstream использует __DATE__/__TIME__ в строке версии. Основная сборка
и подготовка словаря задают SOURCE_DATE_EPOCH=0 по умолчанию (значение
вызывающей стороны сохраняется). Это убирает время запуска компилятора
из бинарного образа, не меняя файлы upstream. Значение и команда GCC
сохраняются в build/pforth.build/compile-env.json и compile.json.

## Ускорение поиска и RV32I

План 8.5–8.7: индекс имён находится в гостевой памяти и исполняется
RV32I-инструкциями. Хост готовит только индекс сохранённого встроенного
словаря. Новые имена, коллизии, переопределения и изменения заголовков
обслуживает гость. Обёртки сохраняют исходники upstream и линейный поиск
для сравнения. Общий планировщик copycode объединяет независимые исходные
копирования до трансляции в emulator; динамические границы и IO изолируются.

Индекс: 4096 корзин, цепочки относительных NFA и ранги порядка видимости
находятся в гостевой памяти. Подготовка читает только проверенные байты
сохранённого словаря (381 имя), не пользовательский Forth. Две функции
в копии единицы трансляции получают другие имена определений, а исходные
вызовы привязываются к гостевым обёрткам; upstream-файлы не меняются.
Новые определения добавляются инкрементально; SMUDGE/IMMEDIATE читаются
из живых заголовков. Записи !/C!/FILL/CMOVE в имя исправляют одну корзину
с сохранением порядка переопределений. Откат CONTEXT удаляет ушедший префикс;
изменённые связи требуют перестроения. Произвольное изменение длины имени
переключает поиск на исходный линейный алгоритм: индекс не сохраняет
неоднозначный кэш пересекающихся заголовков. Состояние индекса входит в
обычный снимок гостевой памяти. --linear-search и --serial-rv32i у build
оставляют явные контрольные варианты для парных измерений.
