# 18.1 часть 1: минимум понятий для длинных копирований (разбор, код не менялся)

> Вычитано 2026-11-03: исправлены определения `%lr` и `long!` в таблице 1а. Разбор описывает текущее устройство (запрос LONG через канал SYS); устройство каналов по замыслу автора (индексасм: каналы — пары полуинтервалов) ещё не описано и может его изменить.

## 1. Минимальный набор слов

Основа: длинное копирование = запись записи LONG (op 6, chan = номер удалённого
пространства, flags = направление, arg = длина в битах, off = позиция) в канал SYS
одним копированием (+ биты данных сразу за записью при записи туда) и, при чтении, второе
копирование из SYS в данные. Всё это сейчас строит `fc-long` (forthc.fth:922).

### 1а. Слова самого копирования
| слово | стек | определение | есть? |
|---|---|---|---|
| `%copy` | ( dl dh sl sh -- ) | одна строка копирования [dl,dh) <- [sl,sh), поля известны при исполнении | есть: генератор `fc-copy-row` (создаёт `fc-long`); в программе ядра -13 |
| `%lr` | ( space pos len dir -- ) | собрать запись LONG (op 6, chan, flags, arg, off) в W = 2^30 + 2^28 | есть, на языке в `fc-long` (через space!/spacec!/%copy) |
| `long!` = `%lst` | ( space pos lo hi -- ) | скопировать биты [lo,hi) данных программы за запись (W + 152) и отправить запись с ними в S | есть |
| `long@` = `%lld` | ( space pos lo hi -- ) | запрос "из", потом копия ответа из SYS в [lo,hi) | есть |
Необходимо строго одно примитивное: `%copy` (копирование с вычисляемыми обеими сторонами
в SYS); `%lr`, `long!`, `long@` выражены из него и из слов п. 1б. Результат: у long@ он
в [lo,hi) данных программы (кортежа "ok/err" нет: ошибки эмулятора = выход 3, диагностика).
Направление - параметр dir (0 в, 1 из), отдельных слов не нужно.

### 1б. Без чего не вызвать
| слово | стек | определение | есть? |
|---|---|---|---|
| `space!` / `spacec!` | ( x lo -- ) | записать 32/8 бит x в позиции [lo,lo+n) | есть (gen-space!); в ядре lo режется до 28 бит блока данных |
| `space@` / `spacec@` | ( lo -- x ) | прочитать 32/8 бит | есть |
| `@ ! c@ c!`, `variable`, `create`, `allot` | | данные программы (`%la`, `%ln`) | есть |
| числовые литералы | | W, S, номер пространства | есть |
| `+ - lshift rshift dup over swap tuck` | | вычисление hi = lo+len, поля | есть |
| `fc-synonym`/`s"`/`fc-eval` | | только для компилятора, программе не нужны | есть |
Итого новых слов для минимума НЕ требуется: есть всё; нет только допуска `%copy` в ядре.

### 1в. Не входит в минимум
- `*`, `/`, `mod`: длина и позиция считаются сложением/сдвигом; умножение нужно лишь для цены.
- `replace`, `price`, `cost`, `proved?`, `check-table`, `accuracy`, `host`, `time`,
  `platform`: механизмы цены/доказательства/платформ (14.x, 15.3), к копированию в
  пространство отношения не имеют (нужны только для оценки и замены определений).
- `throw`/`catch`: убраны (7.2.28).
- Номера хостовых определений (clashes, fill ...) и `hl-*`: это протокол вызова 18.19, а не
  понятие языка; вызов на хосте = частный случай long! в пространство 4096.
- Дальние копирования (общее пространство): его нет; слов под него не проектировать.

## 2. Что значит "доделать длинные"

Мешает сейчас:
1. `fc-long` при `fc-guard`<>0 -> `-13`: `%copy` пишет куда угодно (обе стороны вычисляемы),
   слово непересечения (`dj-prove`, backend.fth:284) такую строку отвергло бы (-9).
2. Нет доказательства для строки в SYS: правила 1-2 допускают из каналов только stdin/stdout.
3. Сам `%lr` пишет запись в W (позиция в пространстве программы, в ядре вне данных блока 2?)
   через space! - в ядре space! режется до 28 бит блока данных, W=2^30+... туда не попадает;
   значит запись нужно собирать в блоке данных программы, а не в W.

Перенос правила 3 (18.20/18.22, host-layout.md разд. 10-11):
- Запрос в SYS = блок в данных программы (блок 2): заголовок (запись LONG, 152 бита) копируется
  ТОЛЬКО из шаблона в коде (блок 0); программа подставляет лишь значения аргументов.
  Для LONG: шаблон держит op=6, flags(dir), поле arg (длина) и chan; программа даёт pos
  (off), lo, hi в своих данных, а не `space`/`len`.
- Для вызова на хосте chan константа (`hl-space`=4096) и это ровно шаблон. Для общего
  случая chan - данные: значит либо шаблон на каждое пространство, либо chan подставляется
  как "адрес-аргумент" (окно доказательства с проверкой диапазона). Выбор - у автора (вопрос 1).
- Доказательство: (а) строка в SYS копирует блок из блока 2 длиной >= заголовок;
  (б) каждая строка, пишущая в заголовок - из блока 0; (в) данные long!/long@ [lo,hi) лежат
  в блоке 2 (для long@: приёмник ответа - в блоке 2). Для `pos` доказывать ничего не надо
  (позиция в чужом пространстве изолирована самим пространством).
- Нужно: окончание заглушек из 11 (ячейки шаблонов; записи между шаблоном и запросом -
  в разд. 11 сняты после 18.22), поэтому основа готова.

Что ещё нужно: (1) откуда у программы номер пространства (вопрос 1); (2) куда long@ кладёт
результат: [lo,hi) блока данных (уже так); (3) тесты: нарушения (заголовок из данных, чужой
приёмник ответа, chan из данных вне выданных) - по образцу `test_disjoint.py` (17 нарушений).

План (оценки по прежним задачам 18.19-18.22):
1. Свести `%lr`/`long!`/`long@` к шаблону заголовка из кода + данные в блоке 2 (как 18.19
   блок вызова); убрать зависимость от W/S-записи через space!. ~ 1 задача 18.19 (средняя).
2. Расширить `dj-sys-ok?`/`dj-heads` на запрос LONG: блок-запрос, `chan`, направление;
   обработать приёмник ответа long@. ~ как 18.20 (+0.5).
3. Снять `-13` из `fc-long` в ядре (guard), включить в наборы ядра (`check-kernel`).
   ~ малая.

   `make check-full` L1=L0. ~ средняя.

## 3. Вопросы автору
1. Кто выдаёт номер удалённого пространства программе: константа компилятора (как
   `hl-space`=4096), аргумент (данные программы, тогда окно диапазона), или выдаёт ядро
   при запуске? Можно ли программе копировать в любое пространство хоста (0 SYS, 1 часы,
   2.. файлы `-r`, 4096 эмулятор) или только в выданные? Пространство 0 (старый SYS) даёт
   обход изоляции: допускать?
2. Направление "из": допускать чтение любых пространств хоста (часы, файлы) в ядре?
3. Запрос LONG в данных программы со своим заголовком из шаблона - принимается как
   единственная форма (по аналогии с решением 2026-11-02, вариант "а")?
4. Нужны ли программе длина/позиции больше 28 бит (позиция в удалённом пространстве - да:
   off 64 бита; граница "узкого" 24 бита, 7.2.26)?
5. Результат/ошибка: достаточно диагностики эмулятора (выход 3), или нужен код возврата
   в данных (без исключений 7.2.28)?
