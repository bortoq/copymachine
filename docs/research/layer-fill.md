# Заполненность слоёв (14.2)

Слой = такт эмулятора; ширина процессора 8 инструкций (`-p 8`), пространство 2^31 бит. Непустая инструкция: копия с непустым источником или канальная с `low != high`. Скрипт: `tools/research/layer_fill.py` (счётчик — `tools/research/layer_fill_trace.c`, копия `checked_vm1.c` с счётчиком вместо аудита; рантайм эмулятора линкуется без изменений). Python-эталон `vm2_reference` не использован: на миллионах тактов он копирует память каждый такт.

## Оценка

Без переделки программ: если бы планировщик заполнял слои полностью, слоёв было бы не меньше `ceil(копирований / ширина)` (нижняя граница; зависимости по данным между копиями не учитываются, поэтому реальная экономия меньше).

| Ширина | Слоёв сейчас (ширина 8) | Нижняя граница слоёв | Экономия тактов |
|---:|---:|---:|---:|
| 8 | 29249544 | 10615575 | 63.7% |
| 16 | 29249544 | 5307788 | 81.9% |
| 32 | 29249544 | 2653894 | 90.9% |

Для сумм: среднее 2.90 непустых инструкций из 8, полных слоёв 4.91%. Строка ширины 8 показывает, сколько дал бы идеальный планировщик уже на текущей ширине; для 16 и 32 нижняя граница достигается только при независимости копий в слое.

## Вывод

Слои заполнены в среднем на 36% (суммарно доминирует L0: он даёт почти все такты). Идеальное заполнение при ширине 8 сократило бы число тактов на 64%, при 16 - на 82%, при 32 - на 91% (нижняя граница числа слоёв; без учёта зависимостей между копиями). Пока планировщик не заполняет слои, ширина 16 или 32 сама по себе тактов не экономит: слоёв не меньше, чем при 8. Выигрыш даёт только перепланировка.
