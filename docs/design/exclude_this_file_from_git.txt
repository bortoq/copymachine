>>      "литерал" — слово, превращающее текст из канала в биты; запись чисел —
>>      заменяемое определение слова "литерал". Мнение автора: всё надо
>>      перенести в язык, иначе он не будет полным.
>> 2.7. Способы проверки — определения слова проверки, заменяемы. [ПРИНЯТО]
>>      Сейчас не выбираем; кандидаты:
>> 2.7.1. полная таблица (малые слова);
>> 2.7.2. параметрические слова: функция для любой ширины n одним правилом;
>>      исчерпывающе проверяется при малых n, большие n порождаются тем же
>>      правилом. Полностью достоверная программа из полностью достоверных
>>      слов; дальше её можно только удешевлять. [ПРИНЯТО 2026-10-27]
>>      Большие функции (например, 64-битное сложение) доказываются не
>>      перебором, а построением из слов, доказанных перебором, по правилу с
>>      известным доказательством (можно брать уже имеющиеся доказательства
>>      алгоритмов). Из языка выделяются полностью доказанные слова;
>>      определение языка пишется на них.
>> 2.7.3. символьное исполнение (BDD — граф решений по битам; у функции одна
>>      сокращённая запись, равенство определений = равенство узлов) — как
>>      программа на language в гесте. Мало для сложения, логики, сравнений;
>>      для умножения/деления — через 2.7.2. Прототип вне геста и замеры —
>>      docs/research/symbolic.md;
>> 2.7.4. хеш полной таблицы: экономит хранение, но не время проверки.
>> 2.8. Определение языка. [ПРИНЯТО]
>> 2.8.1. Все определения языка даны файлом language.md и кодом; вместе они и
>>      есть определение языка (docs/dictionary.md переименовать в
>>      language.md; термины проекта, не относящиеся к языку, — решить, куда
>>      переносить). Запись понятия: текст для пользователя + ссылка на код
>>      слова + артефакт (таблица или способ проверки). Нормативны код и
>>      артефакт; текст их объясняет.
>> 2.8.1.1. [ПРИНЯТО] language.md — определение языка на русском (потом —
>>      перевод на простой английский); синхронизирован с ядром языка:
>>      запись на каждое слово ядра, ссылка на код с хешем определения,
>>      расхождение — ошибка проверки.
>> 2.8.2. Определение языка предъявляется пользователю: он лично видит, что
>>      язык — то, чем заявлен, и соглашается использовать ВС (лицензия, 1.4).
>>      Дальнейшие понятия пользователь передаёт в запросах; принимает их
>>      язык способом, зафиксированным в определении языка (2.2). ВС проводит вычисление
>>      как доказательство с известной пользователю точностью.
>> 2.8.3. ВС публикуется, когда язык рабочий: содержит свой эмулятор как своё
>>      слово и все проверки, подтверждающие, что язык — язык, действия в гесте
>>      — вычисления и т.д. До этого ВС пишется и тестируется до рабочего
>>      состояния. Поэтому эталонные артефакты первых определений проверены
>>      до публикации.
>> 2.9. Слова пользователя. [ОБСУЖДАЕТСЯ] Вопросы автора: как пользователь
>>      задаёт новые слова; как язык решает, добавлять ли определение из
>>      запроса; недоказанные слова придётся разрешить; как хранить
>>      доказательства, если таблица аргументов и результатов больше любого
>>      доступного пространства.
>>      [ПРЕДЛОЖЕНИЕ]
>> 2.9.1. Пользователь передаёт в запросе текст программы: определения и то,
>>      что вычислить. Язык компилирует их в пространство программы
>>      (изолированное от ядра, 1.1) — это слова программы, ещё не слова
>>      языка. Определение пользователя и есть смысл его нового понятия:
>>      эталон для будущих кандидатов — его поведение.
>> 2.9.2. Слово программы становится словом языка (ядра) по тому же правилу
>>      цены (1.5): если хранение определения в ядре (размер входит в цену,
>>      2.4.1) дешевле, чем его повторная компиляция и исполнение в запросах.
>>      Новое понятие сравнивать не с чем — оно принимается недоказанным, с
>>      точностью по полноте проверок (2.3); недоказанное исполняется со
>>      стоп-словом (1.8). Определение пользователя для уже существующего
>>      понятия — кандидат (2.2).
>> 2.9.3. Доказательство не хранится таблицей. Самое компактное хранение
>>      таблицы — само определение: прежние определения остаются в стеке
>>      определений (2.2.4), и их значение на любом аргументе можно вычислить
>>      заново. Храним: определение; описание проверенного множества
>>      аргументов (например, "все n-битные при n<=8", "k наборов из
>>      запросов"); способ проверки (перебор, сведение к предыдущей версии
>>      языка — цепочка использованных равенств, BDD, правило 2.7.2). Полная
>>      таблица хранится только для малых слов (2.1.4).
>> 2.10. Ядро языка и бут. [ПРИНЯТО]
>> 2.10.1. Из языка выделяется ядро языка — механизмы, которые не выражаются
>>      другими словами.
>> 2.10.2. Определение языка пишется словами ядра языка.
>> 2.10.3. Бут — механизм компиляции языка в копикод из определения языка.
>> 2.10.4. Программы пользователя — слова, определения которых не дорожают
>>      при каждой перекомпиляции языка.
>>      [ПРЕДЛОЖЕНИЕ] Механизм 2.10.4: при перекомпиляции языка программы
>>      пользователя перекомпилируются; новый код принимается, если его цена
>>      не выше, иначе остаётся прежний (стек определений, 2.2.4).
>> 2.10.5. Что уже есть (факт): ядро K — около 1100 строк Forth (prelude,
>>      backend, compute, forthc, main, kernel); исходник компилируется в
>>      индексный код и воспроизводит себя (K1 == K0). Генераторы копикода
>>      (cc-copy, cc-layer, cc-table и др., backend.fth, compute.fth) — уже
>>      слова Forth. Но примитивы языка (DUP, +, @, IF, DO, EXECUTE, ...)
>>      заданы 94 ветвями по имени внутри компилятора (fc-is?, forthc.fth) и
>>      повторены в model.py — их нельзя заменить. forthc.fth исполняется и
>>      32-битным pForth на хосте (поток равен потоку модели, секунды), и
>>      самим ядром в гесте (пересборка K1 — 84 мин).
>> 2.10.6. [ПРИНЯТО] Ядро языка — слова языка, использованные в
>>      определении языка; определение языка не содержит ничего, кроме слов
>>      языка (замкнуто: каждое использованное слово в нём же определено).
>>      Ядро не объявляется, а вычисляется по графу определения. Для этого
>>      в язык добавляются: литералы как полуинтервалы (позиции с постоянными
>>      битами), цифры — синонимы некоторых литералов, числа, мелкие
>>      механизмы из копирований и, возможно, многое другое. Основание —
>>      слова-копирования (2.1.1): определение инструкции — она сама.
>>      Компиляция — преобразование определения на языке в определение на
>>      инструкциях пространства.
>> 2.10.7. [ПРЕДЛОЖЕНИЕ] Бут без model.py: model.py — механизм вне геста
>>      (2.6.6) и требует повторять каждое слово-генератор на Python. Первый
>>      K0 строит forthc.fth на хостовом pForth или прежний K в гесте; дальше
>>      язык компилирует себя сам. Проверка перекомпиляции — артефакты: все
>>      программы тестов выдают то же, что прежде, и язык воспроизводит себя.
>> 2.11. Механизмы слова: цена, тип адресации, доказательство. [ПРИНЯТО]
>> 2.11.1. К механизму "слово языка" добавляются механизмы: цена; тип
>>      адресации — слово может исполняться в копипространстве, в
>>      индекспространстве и в хост пространстве (каким бы оно ни было);
>>      механизм доказательства.
>> 2.11.2. Экономно: для доказанных слов механизм доказательства — функция из
>>      таблицы с одним однобитным значением.
>> 2.11.3. [ПРИНЯТО] Экономия через общие слова: таблица "доказано" —
>>      одно слово на весь язык, доказанные слова ссылаются на него (цена —
>>      одна ссылка). У недоказанных — описание проверенного множества и
>>      способ (2.9.3). Тип адресации — свойство определения, а не понятия:
>>      у понятия может быть по определению на каждый тип пространства, из
>>      них выбирается самое дешёвое (1.5).
>> 2.11.4. [ПРИНЯТО 2026-10-27] Тип адресации — номер платформы: позиция
>>      таблицы "платформа", которой соответствует пространство, где
>>      определение исполняется и проверяется, и способ запуска там. Язык
>>      содержит слова, превращающие любое определение в определение,
>>      готовое к исполнению на хосте.
>> 2.11.5. [ПРИНЯТО 2026-10-27] Время двух определений равно, если разница
>>      меньше погрешности измерения на платформе (повторные запуски).
>>
>> 3. Эмулятор и хост.
>> 3.1. [ПРИНЯТО] Эмулятор — исполнитель гест пространства плюс хост
>>      пространство, управляемое программами на language из геста.
>>      [ПРИНЯТО 2026-10-27] Пространство — слово языка: понятие
>>      "пространство", определение — эмулятор, в основном слова с
>>      определениями, исполняемыми на хосте. Логика хоста считается в
>>      гесте: решение о любом действии на хосте принимает копикод геста, хост
>>      выполняет только само неделимое действие. Эмулятор становится
>>      универсальной программой: управляя им из геста, можно выполнить на
>>      хосте что угодно; внешняя граница — права пользователя ОС.
>> 3.2. Хост пространство. [ПРЕДЛОЖЕНИЕ]
>> 3.2.1. Хост пространство — виртуальная память процесса эмулятора
>>      (позиция = 8 * адрес; до 2^47 байт, поле инструкции >= 51 бит,
>>      bitcopy поддерживает до 64). Гест — диапазон внутри неё. Указатели,
>>      которые возвращают ОС и библиотеки, сразу являются позициями.
>> 3.2.2. Устройства процесс видит только через ОС: файлы /dev, /sys, /proc,
>>      системные вызовы, библиотеки. Память устройства, отображённая mmap
>>      (буфер GPU, кадровый буфер, регистры PCI через VFIO/UIO), и файлы,
>>      отображённые mmap, — обычные позиции: чтение и запись — копирование.
>>      Потоки (терминал, канал ОС) позиций не имеют — окно фиксированной
>>      длины.
>> 3.2.3. Адресация позиционная. Ассоциативная (по имени, пути) — слово языка
>>      поверх позиций, значит заменяема.
>> 3.2.4. Только bitcopy: сетевой вариант (3.8) хост пространство не
>>      поддерживает.
>> 3.3. Протокол хост-гест. [ПРИНЯТО] Язык содержит протокол общения хоста
>>      и геста (слова языка, заменяемы). Протокол уже есть — SYS
>>      (emulator/src/proto.def), но сделан по-старому: несколько адресуемых
>>      действий (CLOSE, SEEK, FSTAT, IOCTL, EXEC, каналы S..S+5) вместо
>>      одного — длинного копирования в позиции хост пространства. Задача —
>>      переопределить протокол на длинном копировании: "всегда успешное
>>      чтение или канала нет"; статус, EOF, число переданных бит, причина
>>      ошибки — данные в позициях хоста, обновляемые на границе такта.
>>      Сейчас (факт): канал — вырожденный операнд [C,C], C>=S, длину задаёт
>>      буфер. Места использования SYS — docs/research/sys-usage.md.
>>      [ПРИНЯТО 2026-10-27] Берётся имеющийся протокол SYS и переделывается
>>      под новое определение языка: действия старого протокола получают
>>      обёртку, эмулирующую длинное копирование. Длинное копирование —
>>      копирование в удалённое пространство: изолированное от данного и с
>>      другой адресацией.
>> 3.4. Функции хоста. [ПРИНЯТО, кроме помеченного]
>> 3.4.1. Интерфейс из геста один: скопировать значения в нужные позиции хоста
>>      (процессор и часть остального хост пространства). На стороне хоста
>>      механизмов исполнения может быть несколько.
>> 3.4.2. Гест не знает архитектур и платформ: передаёт имя функции и
>>      аргументы, хост исполняет. Функция указывается именем при каждом вызове
>>      (как проще); связывание имени с позицией вызова — позже, как более
>>      дешёвое определение. Протокол — слова языка, переопределяем (в том
>>      числе позже — на машинный код из геста).
>> 3.4.3. Для геста функция хоста — таблица, содержимое которой вычисляет
>>      хост: аргумент копируется в позиции, результат забирается на следующем
>>      такте (как поиск по таблице с вычисленным индексом). Это определение
>>      понятия, как любое другое: используется, если дешевле (1.5).
>> 3.4.4. [ПРЕДЛОЖЕНИЕ] Долгие и блокирующие вызовы — асинхронно, готовность —
>>      позиция-флаг; для ввода/вывода ОС даёт такой интерфейс в памяти —
>>      io_uring. GPU — через библиотеку (CUDA driver API / Vulkan); ядро GPU —
>>      определение понятия; слой копирований с непересекающимися
>>      интервалами параллелен по данным, поэтому определение слова
>>      "эмулятор" — кандидат на исполнение на GPU.
>> 3.4.5. Накладные расходы: запуск программы хоста — миллисекунды. Небольшие
>>      функции — в эмуляторе: гест переписывает и пересобирает эмулятор,
>>      добавляя функцию и получая к ней быстрый доступ (3.5). Улучшать язык
>>      можно, улучшая эмулятор.
>> 3.5. Замена эмулятора. [ПРИНЯТО]
>> 3.5.1. Гест строит код нового эмулятора, поднимает на нём новое
>>      пространство и вычисляет в нём язык, использованный для создания
>>      нового эмулятора; значение должно совпасть со значением в
>>      пространстве, инициировавшем замену (1.7 для слова "эмулятор").
>> 3.5.2. Идея автора: гест через запуск на хосте создаёт новое пространство
>>      нужного размера, копирует себя в него через каналы, продолжает работу
>>      там и завершает старое. SYS EXEC для запуска на хосте уже есть.
>> 3.6. Позиции, через которые значения приходят извне (каналы ввода, функции
>>      хоста с недетерминированным результатом), автор думает считать
>>      управляющими каналами; это требует слов "управление", "пользователь".
>>      [ОТЛОЖЕНО] Остальная часть языка делается без них. Их значения
>>      считаются битами, прочитанными через канал (аргументами, 2.1.4); в
>>      замене эмулятора (3.5.1) сравниваются только значения, не зависящие от
>>      них.
>> 3.7. Изоляция (1.3): цепочка механизмов от логики до копирования
>>      непересекающихся полуинтервалов в одном слое (факт):
>> 3.7.1. сетевой вариант доказывает, что копирование непересекающихся
>>      полуинтервалов слоя реализуемо без сложения адресов (3.8);
>> 3.7.2. непересечение обеспечивает гест, а не хостовая часть эмулятора:
>>      планировщик в гесте (forthc.fth, "straight-line scheduler", fc-place и
>>      cc-fits? из backend.fth) кладёт копирование в слой, только если оно ни
>>      с чем не пересекается; таблица, адрес чтения которой вычисляется при
>>      исполнении, читается не более одного раза за слой (fc-has?). Хостовые
>>      планировщик и оптимизатор (Python, copycode.vm1) делают то же для
>>      старых путей;
>> 3.7.3. checked-emulator (только в тестах) дополнительно проверяет каждый
>>      такт при исполнении;
>> 3.7.4. изоляция ядра от программ пользователя в K: @ ! C@ C! проверяют
>>      адрес (THROW -9), приёмник кода программы пишет только в её половину
>>      пространства (kn-put).
>> 3.7.5. Не сделано: слово, доказывающее непересечение позиций программы
>>      (сейчас непересечение обеспечено построением кода). По коду (не
>>      проверено запуском): SPACE!/SPACEC! — примитивы без проверки половины
>>      (forthc.fth:729, 775), и EXECUTE переходит по любому числу — программа
>>      пользователя, похоже, может писать в ядро и исполнять его код с
>>      середины, что нарушает 1.1.
>> 3.7.6. Хост и гест — части одного целого (0.9); весь контроль — в гесте,
>>      изоляцию может нарушить только копикод геста, а он проверяется.
>>      Хосткод (код в инструкциях процессора хоста) — не копикод: схему его
>>      изоляции автор изложит позже. [ПРЕДЛОЖЕНИЕ] хосткод в отдельном
>>      процессе, которому ОС отображает только его позиции.
>> 3.8. Размеры. Размер геста задаётся при запуске (-s). Сетевой вариант —
>>      модель аппаратного механизма копирования (сравнения и перенос ключей
>>      через сортирующую сеть); ключи 16-битные, поэтому S<=65520, P<=128.
>>      Ограничение не принципиальное: ширина ключа может быть
>>      bit_length(S); но сеть растёт как N log^2 N и программно для больших S

7.2. Решения и уточнения автора (2026-10-30):
7.2.1. [ПРИНЯТО] Расходы — три измерения: биты, копирования, слои.
7.2.2. [ПРИНЯТО] Виртуальное пространство не находится на хосте: оно
     существует и выполняется как анонимные копирования. Хосты делают
     локальные, длинные и удалённые копирования, не зная, что делают;
     общее пространство ведёт учёт (изолированно от пользователей) и
     дирижирует копированиями.
7.2.3. [ОТКРЫТО] Общий язык не существует одним экземпляром — это
     совокупность языков, которые могут различаться. Варианты: языки
     пользователей торгуют определениями, и это эмулирует общий язык (новый
     пользователь покупает за ресурсы своего хоста виртуальное пространство
     с языком); пространство, принадлежащее самому общему компьютеру
     (нежелательно: ломает цельность концепции).
7.2.4. [ОТКРЫТО] Достоверность. Варианты: заказывать одно вычисление у
     разных пространств; проверять пространство; полностью изолировать
     вычисления от пользователей и пространств (никто не знает, что
     вычисляет, — подделать нельзя).
7.2.5. [ПРИНЯТО] Взаиморасчёты — после остального.
7.2.6. [ПРИНЯТО] Бут — на языке, pForth удаляется, зерно — готовый L0.
7.2.7. [ПРИНЯТО] Сообщения и коды ошибок эмулятора — часть определения
     эмулятора; годится любое работающее поведение.
7.2.8. [ПРИНЯТО] Название — «общий компьютер»: кратко и информативно.
7.2.9. [ПРЕДЛОЖЕНО] Скорость сборки без pForth: долгие определения
     исполнять на хосте (платформа 1, длинные копирования); целиком —
     язык переводит своё определение компилятора в C (расширенный `host`),
     сборка — `cc`. Замер и оценка — 18.2.
7.2.10. [ПРИНЯТО] Бут на Python-модели (вариант D замера 18.2) не нужен.
7.2.11. [ПРЕДЛОЖЕНО] Перевод в код хоста (вариант E) годится и для
     изменения эмулятора из пространства: добавить эмулятору определения
     нужных слов на хосте с быстрым доступом и вызывать их из
     копипространства; копипространство может как угодно менять свою
     эмуляцию. Либо кросскомпилятор в код хоста в копипространстве готовит
     хосткод и только передаёт его эмулятору на исполнение. Пока не
     принципиально.
7.2.12. [ВОПРОС] Длинные копирования — копирования к хосту как к
     пространству; их можно планировать составителем расписаний так же,
     как короткие (тот же механизм для компиляции определений и для
     длинных копирований).
7.2.13. [ПРИНЯТО] Слово может иметь сколько угодно определений, в том
     числе разные определения для разных платформ, где оно исполняется
     (не «слово определено дважды», а «у слова два определения»).
7.2.14. [ПРИНЯТО] Цена слова пока — время исполнения его определения;
     поэтому многие слова выгоднее исполнять на хосте. Три метрики
     копипространства (биты, копирования, слои) для определений в
     копипространстве хранить: они понадобятся для полного расчёта
     стоимости вычислений.
7.2.15. [ПРЕДЛОЖЕНО] Исполнение определения на хосте: аргументы длинным
     копированием из копипространства к хосту, определение хоста (для
     умножения — одна-несколько инструкций), результат длинным
     копированием обратно. Тогда эмулятору не нужно знать, где в
     копипространстве лежат данные компилятора, а проверка непересечения
     видит все интервалы (это обычные копирования). Опыт 18.11 сделан
     иначе: C-слово само читает и пишет копипространство по адресам
     компилятора.
7.2.16. [ПРИНЯТО] С правильным исполнением определений на хосте pForth
     заменяется языком; что не умеет pForth — не важно.
7.2.17. [ПРЕДЛОЖЕНО] Вызов определения на хосте — несколько тактов, а не
     ~100 (опыт 18.11): у эмулятора собственное пространство (массив
     переменных); копикод копирует значения в канал; эмулятор (протокол
     вкомпилирован или настраивается при старте) раскладывает их в
     заранее известные места, на которые настроено определение, и
     исполняет его. Данные, которые определение обходит, пока держать на
     хосте постоянно (если места немного).
7.2.18. [ПРИНЯТО] Названия компиляторов: компилятор языка (`language/src`;
     в копипространстве — L0), составитель расписаний (часть компилятора
     языка), транслятор host (язык → C), cc (компилятор C хоста), pForth
     хоста (уйдёт). Префикс составителя расписаний `cc-` заменяется на
     `lay-` (раскладывает копирования по слоям).

7.2.19. [ПРИНЯТО] Слову сложения (и другой арифметике: `-`, `and`, `or`,
     сравнения) дать определение на хосте; вызовы определений на хосте
     разрешены и программам, не только коду ядра (2026-10-31).
7.2.20. [ПРИНЯТО] Без слова-обёртки: вызов определения на хосте
     подставляется на месте использования слова; аргументы копируются в
     блок вызова прямо с мест, где лежат; запасной путь (например,
     невыровненный `fill`) — внутри определения на хосте (2026-10-31).
7.2.21. [ПРИНЯТО] Ошибки вызова определения на хосте и длинного
     копирования — ошибки разработки, а не эксплуатации: длинные
     копирования должны работать; пока идёт разработка, в протокол можно
     добавить диагностику, а найденные ошибки исправлять (2026-10-31).
7.2.22. [ПРИНЯТО] Изоляция — свойство построения кода языком: в
     копипространстве исполняются только копирования, которые расставил
     язык, нарушить изоляцию может только неверно написанный язык.
     Проверки при исполнении (14.10) — временные, их убрать. Для
     копирований, позиция которых вычисляется при исполнении (`space!`,
     `space@`, `execute`), — динамическая изоляция: в строку копирования
     вписываются только младшие биты адреса (смещение в области
     программы), старшие — константа компилятора; такое копирование одно
     в своём слое. Слово непересечения (3.7.5) доказывает это для
     скомпилированной программы при компиляции (2026-10-31).
7.2.23. [ПРИНЯТО] Ширину интервала `space!`/`space@` (32 или 8 бит)
     задаёт слово, программа даёт только начало (2026-10-31).
7.2.24. [ПРИНЯТО] Всё, что язык делает на хосте, — длинное копирование:
     язык раскладывает значения по позициям пространства эмулятора,
     которые сам задаёт при построении эмулятора; номер определения —
     в «процессор» хоста, аргументы — в заранее заданные позиции;
     эмулятор, увидев номер, исполняет определение и копирует результат в
     позицию, тоже заданную языком. Ошибки — только ошибки отладки языка
     (2026-10-31).
7.2.25. [ПРИНЯТО] Позиции результата вызова на хосте — в блоке вызова
     (их задаёт вызов, результат ложится прямо в регистр). Сверка
     заголовка раскладки эмулятора с текстом языка — в проверках языка,
     не эмулятора. Текст ядра не помещается в буфер — сократить
     комментарии в тексте ядра (подкачки текста нет) (2026-11-02).
7.2.26. [ПРИНЯТО] 18.18: слово непересечения без правила непересечения
     строк слоя (его соблюдает составитель расписаний при построении);
     замена определений (14.13) в программе — ячейка понятия по образцу
     `execute` (вписывание из записи слова в данных); граница «узкого»
     вписывания — 24 бита; проверки адреса у `@ ! c@ c!` (-9, -23)
     убрать — вместо проверок планирование (2026-11-02).
7.2.27. [ПРИНЯТО] `execute`/`catch`: xt — номер слова в таблице входов,
     которую строит компилятор; переход только на вход слова, по
     построению. Область `space!`/`space@` — выбор исполнителя
     (автор 2026-11-02: «сделай пока этот выбор сам, так чтобы его было
     легко изменить»): младшая половина блока данных программы (28 бит),
     ширина области — одна именованная постоянная компилятора.
     Общее требование автора: в языке всё должно быть легко изменить.

7.2.28. [ПРИНЯТО] Без исключений (18.21), автор 2026-11-03: слова языка
     `throw`/`catch` убраны; ошибка текста программы — сообщить и
     отвергнуть программу; останов — копирование нопов в процессор;
     пределы языка — увеличить ёмкость. Общий принцип: нерешённое
     объявляется решённым с запретительной ценой и удешевляется по мере

7.2.32. [ОТКРЫТО] Общее пространство (этап 22), автор 2026-11-04: до

     пространство, выполняемое усилиями всех хостов» — ещё слишком

     каждый такт адресовать все биты, каждый в своей фазе (механизм
     автор предложит, когда понадобится). Вычислительная система должна
     предусматривать всё это, иначе не сможет конкурировать по
     производительности с существующими.

7.2.35. [ОТКРЫТО] Изолированные уровни, одно слово на уровень, автор
     2026-11-05: языки не только вложены, но и изолированы — язык N
     пользуется только словами языка N−1. Определения слов тогда можно
     менять как угодно, не меняя самих слов (на них написан следующий
     язык): язык идеально модифицируем. На каждом уровне одно слово —
     универсальное, через которое определяются все остальные; это
     копирование (NOR/NAND универсальны только для логики без памяти,
     соединение — опять копирование). Уровни снизу вверх добавляют
     копированию свойства (индексное, с тремя аргументами, длинное,
     подкачка, дальнее, общее пространство, межпользовательское, учёт
     расходов), выбор по цене не платит за ненужные. Расширение языка —
     программа на словах верхнего уровня. Доступ разделён: пользователь
     добавляет в верхний (свой) уровень что угодно; язык добавляет новый
     уровень только при доказательстве слова (таблица всех значений или
     отметка, что таблица проверена, но не хранится из-за размера). Все
     сложные (недоказанные) вычисления — в последнем, пользовательском
     уровне. Изоляция стоит 0 тактов: каждый уровень — компилятор в
     нижний, в образе остаётся язык 1. Вопросы: как доказать уровень
     копирования (таблицу не перечислить — например, полный перебор на
     малом пространстве и доказательство, что определение не зависит от
     размера); обещание без опоры на такт («по завершении назначение
     равно источнику» и когда завершение видно); скрытые помощники
     (сложение внутри определения уровня) повторяются — сливать
     одинаковые таблицы по отпечатку внизу, в образе. Нарушения в
     нынешней цепочке: l3c читает слова языка 4 (23.17), подкачка 23.19
     опиралась бы в языке 3 на long@ языка 4; язык 3 с 24 словами — не
     уровень в этом смысле, а язык определений.

7.2.37. [ОТКРЫТО] Доказательство бесплатной проверкой, автор 2026-11-05:
     пользователь всё равно делает свои вычисления и платит за них; ВС
     выполняет их за него и заодно — проверки, нужные для доказательства
     слов своего языка; они совпадают, поэтому накладные расходы на
     корректность ВС — 0. Большие доказательства (за обозримое время не
     проверить) — статистическими методами. Язык имеет слово,
     осуществляющее доказательство; его определения тоже улучшаются.
     Тонкость: вычисление — проверка, только если есть второй независимый
     результат: (1) определение и есть обещание (таблица) — проверять
     нечего; (2) проверить дешевле, чем вычислить (деление — умножением);
     (3) многие пользователи считают одно слово на одном входе — ВС отдаёт

     — проверка; экономия на повторах оплачивает проверки в сумме.
     Вероятностные методы: случайные входы, Фрейвалдс, PCP; у слова —
     степень уверенности, растущая с вычислениями пользователей.

7.2.38. [ПРЕДВАРИТЕЛЬНО] Общее пространство: воркеры, очередь, хранение,
     автор 2026-11-08 (к 7.2.32; синхронизатор и BSP отвергнуты как
     слишком ограниченные). Пометка «(улучшить)» — место, требующее
     доработки.
     Такт. Малые пространства — воркеры, работающие над вычислением
     общего пространства; общее пространство — очередь заданий на
     копирования: его процессор, слой копирований, уже согласованных
     языком (непересечение). Быстрые и медленные воркеры берут куски
     слоя и выполняют их; общий такт — исчерпание слоя; следующий слой
     пишут копирования текущего, как в малом пространстве. Из
     непересечения: порядок не важен; повтор безвреден (источник за слой
     не меняется), поэтому задание не захватывается, отстающий кусок
     выполняет ещё раз быстрый воркер; потерянный ответ — повтор.
     Повторное выполнение — заодно проверка (7.2.37).
     Хранение — определение слова «пространство». Обещание: позиция p в
     такте t имеет то значение, которое дала бы одна машина копий на том
     же тексте; где лежат биты — определение, их может быть несколько,
     выбор по цене, проверка — как у любого слова (перебор на малом
     общем пространстве и проверки при работе).
     - Каталог «участок → хранители» лежит в самом общем пространстве,
       деревом; верх дерева есть у всех. Хеш адреса (Chord, Kademlia) —
       другое определение, без каталога, но без соседства адресов
       (улучшить: когда что дешевле).
     - Хранитель держит свои участки и выполняет задания, пишущие в них
       (работа к данным); биты источника, лежащие у других, — дальним
       копированием; мелкие задания объединяются в куски (улучшить:
       правило объединения и назначения по цене).
     - Перенос участка = копирование бит + запись в каталог, обычные
       задания очереди; подкачка, перенос и балансировка — одно (7.2.34).
     - Копии участка: k хранителей выполняют те же задания и сходятся без
       протокола согласования; отпечатки копий после слоя сравниваются —
       расхождение указывает на неисправного хранителя, его копия
       пересоздаётся; пропавший хранитель заменяется так же (улучшить:
       k — одно, по цене или по доверию к хранителю).
     - Версии: слой t читает состояние t, пишет t+1; две версии держатся
       только у участков, в которые пишет текущий слой.
     - Рост: сначала одно пространство и каталог из одной записи;
       новый хранитель — деление участка и переезд половины копированием.
     - Конец слоя считает хранитель участка за свой участок: общего
       барьера нет, участок переходит к следующему слою, когда выполнены
       все задания, которые в него пишут (улучшить: как задание следующего
       слоя узнаёт готовность своих источников у других хранителей).
     - Единица хранения — размер участка (улучшить: одна или по областям
       по цене).
     - Доверие: чужой хранитель может вернуть неверные биты — повтор,
       сравнение отпечатков, учёт по цене (улучшить: связь с кошельком
       18.7).
     Граница в малом пространстве: интервал, конец которого не
     помещается в адресацию, не выражается строкой этого уровня — его
     выражает уровень выше (разбиение на куски, запрос хосту с широкой
     позицией, как long!/long@). Сейчас эмулятор интервал [lo,hi) с
     lo < S < hi не проверяет и копирует за конец памяти (контракт: вне
     допустимой программы) — по принципу «ошибок нет» часть за S должна
     читать нули, запись — пропадать (улучшить эмулятор).

       построением; он же не даёт внутренней программе выйти за своё
       пространство.
     - Внутренний такт = для каждой из P′ строк внутреннего процессора
       скопировать четыре поля в строку-шаблон внешнего процессора и
       исполнить; если P′ не помещается во внешний слой — несколько слоёв.
       Безвредно для допустимой программы (непересечение ⇒ порядок не
       важен).
     - Каналы: внутренние коды ≥ S′ отображать на внешние каналы/хост;
       единственная настоящая проверка «поле ≥ S′» = сравнение старших
       бит с единицами + таблица по младшим трём.
     - Останов: все P′ строк NOP; проверка «источник пуст» ~P′ сравнений
       за такт — самое дорогое; дешевле — внутренняя программа сама даёт
       признак завершения.
     - Итого несколько десятков слоёв на языке 3; цена ~2·P′ внешних
       тактов на внутренний такт. Для доказательства замены годится.
     - Главное: это не «эмулятор внутри», а уровень в смысле 7.2.35
       (копирование со свойством «адрес относительно вложенного
       пространства»); общее пространство 7.2.38 — тот же уровень,
       направленный наружу.
     - Доказательство по схеме 23.21: на малом A все строки; определение
       параметрично, кроме сравнения с S′.

     Хостовое определение, два пути: (а) цельный C — есть сейчас, дёшево,
     но недоказуемо (доверие к тексту и gcc), на голом железе gcc нет —
     тупик для цели «язык содержит всё»; (б) разбор на слова с малыми
     определениями, у каждого два определения (копипространство + хост);

7.2.41. [МОЗГОВОЙ ШТУРМ, НЕ РЕШЕНО] Слой языка = пространство,
     эмулируемое на предыдущем; каналы как тип доступа. Автор 2026-11-10.

     Мысль автора.
     1) Копирование вводится эмуляцией пространства, где оно
        выполняется: слово предлагает определение пространства с
        3-аргументным копированием на пространстве с 4-аргументным.
        Каждый слой языка добавляет новое пространство, эмулируемое на
        старом; представление копирования меняется, на последнем слое
        это Форт.
     2) Программа пользователя из канала пространство вводить не
        обязана и обычно не вводит: выполняет действие, язык не
        меняется.
     3) Пока слои добавляем мы; язык можно сделать самомодифицирующимся,
        тогда его образ полностью изолирован (доступа ниоткуда).
     4) Канал, в который можно писать из копипространства, — адресное
        пространство с другим типом доступа: не «копируемые интервалы
        не пересекаются», а «при записи значение можно одновременно
        прочесть» (автор: «если не ошибаюсь»). Механизм канала =
        эмуляция пространства с этим свойством. Язык может вносить
        одновременные изменения в определения двух пространств (тип
        доступа — одновременное чтение из одного источника) и так
        решить «канал SYS»: сам вводить формат общения хоста и гостя.
     5) Язык модифицируется только введением новых пространств-слоёв;
        но не требование: в последнем слое пользователю удобны
        дополнительные слова и действия. Действие — слово, определение
        которого можно исполнить (поместить в «процессор»); определение
        слова, не являющегося действием, в процессор помещать нельзя.

     Наблюдения ассистента (не решения).
     а) Компиляция — та же эмуляция, выполненная заранее: у слоя два
        определения одного пространства — исполнять текст при работе
        (нужно, когда текст приходит при работе) и перевести заранее
        (0 тактов); выбор по цене (7.2.34). Уровень 5 из 7.2.40
        («вложенное пространство») тогда не отдельный уровень, а общий
        вид всех уровней.
     б) Определение пространства = вид адреса, запись копирования, тип
        доступа (что можно в один такт), где процессор, отображение в
        нижнее пространство. Новое понятие одно — тип доступа.
     в) «Записал и тут же прочли» сводится к «два чтения одного
        источника»: A→канал и канал→B в одном такте = A→канал и A→B.
        А два чтения одного источника на базовом типе — размножение за
        лишний слой. Тогда канал — не место, а копирование с концами в
        разных пространствах (7.2.36), и особый тип доступа один.
     г) Сейчас слои-компиляторы (seed, l2l, l3c) склеены каналами хоста
        (трубы оболочки). Самомодификация начинается с того, что эта
        склейка определена языком: слои — пространства в одном образе.
     д) Формат хост–гость язык может определить, только если сторона
        хоста тоже пространство со строками, которые гость пишет; в
        эмуляторе неустранимо одно — начальное копирование между
        пространствами (строка загрузки). Касается контракта — решает
        автор.
     е) Действие / не действие = можно ли копировать определение в
        процессор; это тоже тип доступа участка (осторожно: не вводить
        типы без решения автора).

7.2.43. [СЛОВА АВТОРА 2026-11-10, РЕАЛИЗАЦИЯ ОБСУЖДАЕТСЯ] Адресации.
     1) Позиционная адресация: позиция -> значение (бит). Реализована
        субоптимально: O(log^2(размер пространства)) вместо обещанного
        логарифма; это надо честно отметить в документации.
     2) Полуинтервальная адресация (не «сокращённая позиционная»):
        адресуются полуинтервалы — меньшая позиция и длина; копирование
        задаётся двумя индексами и одной длиной.
     3) Ассоциативная адресация: адресация по значению, выполняется
        поиском (позиционная — механизмом с сортировкой). Сейчас не
        разделена на слои и размазана по языку.
     4) Согласованность: адресации обратны друг другу. Ассоциативная
        обратна не позиционной (у бита два значения — бесполезно), а
        полуинтервальной: по позиции лежит значение; поиск этого
        значения находит эту же позицию.
     5) Взаимная обратность есть и внутри адресации: индекс <-> позиция,
        ключ <-> значение (по ключу значение, по значению ключ).
        Файловая система — ассоциативная адресация без обратной
        (содержимое -> путь), отсюда дубли и путаница.
     6) Гарантия времени: число тактов пространства, где расположен
        механизм адресации (для позиционной пока тики хоста; уточнится
        при переносе определений хоста в язык). Успех — субоптимальная
        ассоциативная адресация, согласованная с полуинтервальной.
     7) Эмуляция простыми механизмами: таблица ключ -> значение и
        таблица значение -> ключ; посредник — хэш (искать ключ по
        значению); сразу версии значений (стек определений слова: кто
        автор выбранного определения — для кошельков и начисления
        сэкономленного; откаты к старым определениям).
     8) Поиск отсутствующего значения — запретительная цена.
     Решения автора по реализации (2026-11-10):
     9) Кроме хэшей опробовать деревья (таблиц по частям ключа).
     10) Синонимы ключей разрешены: дополнительная таблица синонимов
         каждого ключа.
     11) Стек версий: обратный поиск и выбор — верхняя версия (самая
         дешёвая); пока так.
     12) Первое применение — таблица имён (метки, словарь).
