# 4. Ядро, бут и изоляция

Как язык появляется из ничего и как ядро остаётся целым, пока работают программы пользователя. Понятия бута, L0, L1, самосборки, изоляции построением, доказательства и замены — в [README](../../README.md#понятия). Подробности — [boot.md](../../language/doc/boot.md), [isolation.md](../../language/doc/isolation.md), [proof.md](../../language/doc/proof.md), [replace.md](../../language/doc/replace.md), [user_programs.md](../../language/doc/user_programs.md).

## Бут: откуда берётся первый L0

Определение языка — текст. Чтобы его исполнить, нужен кто-то, кто уже умеет исполнять слова. Первый такой исполнитель — хостовый 32-разрядный pForth (`language/boot/`, лицензия в `license.txt`): `make -C language boot` собирает его (`tools/host.py`), подаёт ему определение (`tools/boot.py`), и он печатает поток — **L0** (15 810 422 байта). Это тот же текст определения, исполненный чужим исполнителем.

Проверка бута — независимая модель на Python (`language/tests/reference/model.py`), которая из тех же файлов строит тот же поток **K0**; бут принят, пока L0 = K0 побайтно (`tests/test_boot.py`).

## Самосборка

L0 — образ, который эмулятор принимает на stdin. Дальше на тот же stdin идёт определение языка и нулевой байт, и L0 пишет в stdout поток **L1**. `make -C language check-self` проверяет: L1 = L0 побайтно. Это занимает около 20 минут (1236 с), потому что эмулятор в сотни раз медленнее хоста. После этого язык компилирует сам себя; pForth нужен только как первое зерно (в плане — убрать, [глава 6](06-plans.md)).

## Раскладка пространства ядра

Пространство ядра — `2^31` бит, поделённое на четыре блока по `2^29`:

| Блок | Что |
|---|---|
| 0 | код программы пользователя |
| 1 | код ядра |
| 2 | данные программы (в ней — стеки, память, регистры) |
| 3 | данные ядра |

Ядро (блоки 1 и 3) занимает верхнюю половину, программа (блоки 0 и 2) — нижнюю. Ядро читает программу из stdin до нулевого байта, компилирует её в блоки 0 и 2, доказывает слоем `dj-prove`, что она не выходит за свои блоки, и запускает (`language/src/kernel.fth`). Остаток stdin становится вводом программы. Раскладка записана в одном месте в начале `forthc.fth` (`fc-bbits`, `fc-abits`) и легко меняется: общее требование автора — в языке всё должно быть легко изменить.

## Изоляция построением

Идея: никаких проверок при исполнении, только правильная расстановка копирований. Вычисляемая позиция (слова `space!`, `space@`, `@`, `!`, `execute`, возврат) вписывается в строку копирования слоем раньше; в программе ядра вписываются **только младшие биты**, а старшие — постоянная компилятора, которая указывает в блок программы. Поэтому:

- `space!`, `@`, `!` попадают только в нижнюю половину блока данных программы; ядро им недоступно;
- `execute` получает не адрес, а **номер слова**; номер указывает в таблицу входов, а таблица — только в слова программы;
- возврат из слова идёт по **номеру точки возврата**: таблица возвратов ведёт только в ячейки после вызовов;
- копирование с вычисляемой позицией стоит в слое одно, чтобы ничто не могло в нём сработать иначе.

## Слово непересечения `dj-prove`

`dj-prove ( first end -- flag )` читает слои скомпилированной программы, как они лежат в пространстве, и доказывает три правила: строки допустимы и лежат в блоках программы; копирование в слои пишет внутри одного поля, а широкое получает от программы лишь младшие биты, и в слое оно одно; длинное копирование ([глава 5](05-long-copy.md)) — только по шаблону запроса. Нарушение — ошибка компиляции `error -9`, программа не запускается. Проверка делается один раз при компиляции, при исполнении её цена — нуль. Непересечение самих строк слоя слово не доказывает: его соблюдает составитель расписаний.

Тесты: `language/tests/test_disjoint.py` (быстро, на хосте: программы принимаются, построенные нарушения отвергаются), `tests/test_isolation.py` (`check-isolation`, долгая цель: пробы, в которых программа пытается задеть ядро).

## Доказательство слова

Слово `check-table ( xt in-bits out-bits table -- ok )` исполняет слово на всех `2^in-bits` наборах и сверяет с таблицей; полное совпадение делает слово **доказанным** (`proved?`). Большие слова предполагается доказывать построением из слов, доказанных перебором. Сейчас ни одно слово ядра не доказано; механизм применён к тестовым словам ([proof.md](../../language/doc/proof.md)).

## Замена определения

`replace ( xt concept -- ok )` заменяет определение понятия определением `xt`, если оно проходит проверку тем же `check-table`, не менее точно и дешевле (на платформах — быстрее по времени, при равенстве — меньше копирований, затем бит, затем слоёв). Прежнее определение уходит в стек определений. Если замена не прошла, `ok` — причина (0 — не слова, 1 — результаты, 2 — точность, 3 — цена). Здесь же правило «программы пользователя не дорожают»: при пересборке языка инструмент `language/tools/user_programs.py` принимает новый код программы пользователя, только если его цена не выше.

## Какие проверки что гарантируют

| Цель `make -C language …` | Что подтверждает |
|---|---|
| `check-closure` | определение замкнуто (`external 0`), список ядра в `core.md` верен |
| `check-language-md` | `language.md` соответствует определению |
| `check-programs` | 37 программ компилируются на хосте и дают ожидаемый вывод на `checked`-эмуляторе |
| `check-kernel` | L0 компилирует и запускает те же программы в своём пространстве |
| `check-self` | L1 = L0 |
| `check-isolation`, `check-proof`, `check-replace`, `check-user-programs` | изоляция, доказательство, замена, неубывающая цена программ пользователя |
