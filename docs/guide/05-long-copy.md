# 5. Длинные копирования и хост

Как программа в пространстве выходит наружу: читает и пишет файлы и устройства, смотрит часы и отдаёт дорогие слова хосту. Понятия — хост, длинное копирование, область, платформа, запретительная цена — в [README](../../README.md#понятия). Справочники: [platform.md](../../language/doc/platform.md), схема запроса — `emulator/src/proto.def`, правила изоляции — [isolation.md](../../language/doc/isolation.md).

## Идея автора

Хост — не набор вызовов операционной системы, а **одно адресное пространство**: его устройства (файлы, диски, часы) — его части, а побитовая позиция в нём — единственное, что надо знать, чтобы копировать туда и оттуда. У этого пространства нет номера: «номера пространств» не существует. Поэтому длинное копирование — такое же копирование, только источник или назначение лежат на хосте.

## Позиция из 128 бит

Позиция в пространстве хоста — `HOST_POS_BITS = 128` бит, записанных числом младшим битом вперёд:

- старшие 32 бита — **область**;
- младшие 96 бит (`HOST_AREA_BITS`) — позиция бита внутри области, так что адресуется любой бит файла Linux (до `2^66` бит).

Область 0 — часы: чтение даёт 64-битное монотонное время хоста в наносекундах, запись пропадает. Области 1, 2, … — файлы и устройства, которые перечислены ключами `-r путь` при запуске эмулятора, по порядку. Побитовая адресация: позиция 0 — старший бит нулевого байта файла.

**Ошибок нет.** Чтение за концом файла, за границей области, из неизвестной области или из файла, который нельзя открыть, даёт нули; запись туда пропадает; эмулятор не завершается с ошибкой. Это решение автора: проблемы и ошибки — слишком высокая цена, поэтому длинное копирование просто должно работать, а недоделанное получает запретительную цену.

## Слова `long!` и `long@`

```
( p0 p1 p2 p3 lo hi -- )
```

`p0 … p3` — четыре 32-битные ячейки позиции, младшая первой (в `p3` — область); `lo`, `hi` — полуинтервал в данных программы. `long!` записывает биты этого полуинтервала в хост на позицию, `long@` читает их оттуда. Размер ячейки позиции программе не мешает: число ячеек (`lay-cells = 4`) выводится из `HOST_POS_BITS`, обе постоянные меняются одной правкой.

Пример для файла `data.bin`, прочитанного как область 1 (байты приходят в числовом порядке, `spacec@` читает бит `k` на позиции `lo + k`, а не старшим вперёд, поэтому буква `H` с кодом 0x48 выйдет байтом 0x12 — полные примеры сверки порядка в `language/tests/test_long_copy.py`):

```
: main  0 0 0 1  1207959552 1207959616 long@
  8 0 do 1207959552 i 8 * + spacec@ emit loop ;
```

```sh
( cat language/build/L0.boot; cat prog.fth; printf '\0' ) \
  | ./emulator/emulator -s 2147483648 -p 8 -r data.bin
```

## Как это работает внутри

Длинное копирование — это запрос `LONG` в канал SYS ([глава 2](02-emulator.md)): запись из операции, канала, флагов (бит 0 — направление), длины `arg` в битах и 128-битного поля `off` (позиция). Данные идут за запросом (запись) или приходят ответом (чтение). Если запись длиннее блока запроса, `long!` отправляет её частями (в ядре — по 65 536 бит); позиция при этом движется с переносом между ячейками.

В программе ядра блок запроса лежит в верхней половине блока данных программы, куда вычисляемые позиции не достают, а заголовок запроса копируется из шаблона в коде. Слово непересечения `dj-prove` ([глава 4](04-kernel.md)) доказывает слоями программы (задача 18.26): в блок запроса пишут только копия шаблона (заголовок), значения длины и позиции (с постоянными целями) и окно данных; ни одно вписывание, узкое или широкое, не достаёт до блока (слово читает цель каждого вписывания); строка в SYS копирует ровно блок запроса и идёт в ячейках после слоя копии шаблона. Поэтому заголовок при любом пути исполнения — нули или шаблон. Не доказано только то, что по пути исполнения нет входа внутрь цепочки слоёв между шаблоном и строкой в SYS (нужны цели всех переходов) — это построение, изоляции оно не нужно.

Цена `long!`/`long@` в оценке компилятора — запретительная (`fc-forbid`): пока это «решено, но очень дорого».

## Определения на хосте

Слово языка можно исполнять на хосте вместо пространства. `: f-host host f ;` объявляет, что определение `f` исполняется на платформе 1 (хост). Компилятор переводит `f` в программу C (допускаются арифметика и логика над 32-битными ячейками, `dup`, `drop`, `swap`, `over` и вызовы других таких слов), хост собирает её командой `cc` и запускает; аргумент и результат передаются длинными копированиями через файл `host.io`, а текст программы — через файл `host.c`. Команды (`cc`, запуск) отправляются запросом `EXEC`. Слово `time ( xt -- ns err )` измеряет время исполнения по часам хоста (область 0): на платформах цена — время, и `replace` выбирает, где слову исполняться быстрее. Подробности и ограничения — [platform.md](../../language/doc/platform.md).

Зачем это нужно: то же вычисление на хосте идёт заметно быстрее, чем в пространстве (самосборка в пространстве занимает около 20 минут), поэтому дорогие слова выгоднее исполнять на хосте.
