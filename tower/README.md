# tower — цепочка вложенных языков 1–5

Единственное описание языка цепочки (этап 23): понятия, все слова всех языков, что работает в пространстве и что пока на хосте, сборка. Другие документы на него ссылаются. Замеры и история шагов 23.x — [docs/measurements/tower.md](../docs/measurements/tower.md).

## 1. Что такое цепочка

Цепочка — несколько языков, вложенных друг в друга. Каждый язык — это несколько слов и **компилятор** в язык ниже; о языках выше он ничего не знает. Самый нижний, язык 1, умеет одно: копировать биты по четырём числам. Языки 1–3 вместе — ассемблер пространства бит (числа, имена, таблицы, переходы); язык 4 — копирование между пространством и хостом (слов у него нет: это то же `copy`, адрес которого лежит в хосте); язык 5 — цена. Сверху — Форт (23.15, решение автора, раздел 3.7). Компиляторы языков 1–3 — программы самой цепочки (написаны на языке 3), каждый работает в своём пространстве; цепочка собирается из текста языка 1 без Python (раздел 6). Ошибок нет: неверный текст — это сообщение в stderr и останов (7.2.28).

## 2. Понятия

Бит, пространство, позиция, полуинтервал, копирование, NOP, процессор, такт, слой, непересечение, устройство, хост — как в [словаре](../docs/dictionary.md#понятия). Ниже только то, что нужно цепочке.

- **Строка** — запись одного копирования в самом пространстве: четыре числа `dl dh sl sh` (в README — «псевдоинструкция»): записать биты источника `[sl,sh)` в назначение `[dl,dh)`. Число занимает **A** бит (младший бит первым), строка — 4A бит. Позиций **S = 2^A − 6**; шесть старших кодов — каналы. Источник длины 0 — NOP.
- **Процессор, такт, слой.** Процессор — первые **P** строк пространства. За такт все они читаются и их копирования выполняются одновременно; записанное видно со следующего такта. **Слой** — строки, работающие в одном такте. Процессор — часть пространства, поэтому строки переписывают строки.
- **Переход.** Последняя строка слоя копирует в процессор текст следующего слоя (он хранится в пространстве). Другого управления нет: цикл, ветвление, вызов — переходы. **Останов** — переход в слой из одних NOP.
- **Канал.** Если оба конца назначения равны `C ≥ S`, строка пишет в канал; источник `[C,C]` — читает. `S+1` — stdin, `S+2` — stdout, `S+3` — stderr, `S` — запросы SYS к хосту (язык 4). Длину обмена задаёт другая сторона. В `copy` канал записывают числом (3.5): слой узнаёт его по адресу. Число зависит от A (`1048572` при A=20), поэтому в тексте языка 4 канал записывают отсчётом от конца пространства: `+k` — это S+k (`copy +2 &x` — как `emit &x`, `copy &x +1` — как `key &x`, `copy +3 &x` — как `warn &x`; `+0` — SYS); `l4c` переводит `+k` (k от 0 до 5) в число, которое читает `l3c`, остальное не трогает. Это форма адреса, не слово; `emit warn key` остаются сокращениями.
- **Образ** — что подаётся эмулятору на stdin: загрузочный слой (его первая строка копирует остальное из stdin на место) и снимок — начальное содержимое пространства. Запуск: `emulator -s S -p P < образ`.
- **Порядок бит.** Позиция 0 — старший бит нулевого байта. Байты потока идут старшим битом вперёд, числа (поля строк, данные) — младшим. Поэтому символы пишут как строки (`"Hi"`), а не как числа.
- **Косвенность.** Строка лежит в процессоре, то есть в пространстве: предыдущая копия может записать число в её поля, и строка скопирует то, на что оно указывает. Это единственный способ взять данные по вычисляемому адресу.
- **Таблица** — функция, заданная всеми значениями: 2^K записей по w бит; запись i лежит в i·2^j от начала (2^j > w, чтобы конец записи не перенёсся в биты индекса), начало выровнено по размеру таблицы. Значение берёт косвенность: индекс копируется в поля источника строки, строка копирует запись.
- **Блок** — цепочка слоёв с именем, заканчивающаяся переходом. Строки блока по слоям раскладывает компилятор так, чтобы строки одного такта не пересекались. **Слово языка** — название действия в тексте (`copy`, `lut`); слово `word` (вызываемый блок с одной ссылкой возврата) — одно из слов языка 3.
- **Метка и ссылка.** `:имя` называет место или определение, `&имя` — его число; `&имя[lo:hi]` — часть данных. Имена есть только в тексте, в образе их нет.
- **Зерно** — то, с чего цепочка собирает себя (как hex0 в stage0): эмулятор, образ кодера `seed.img` и тексты языка 1.
- **Цена** — набор `(rows, layers, bits, ticks)` и одно число из него (язык 5). **Запретительная цена** 2^24 — у пути с неизвестным числом проходов.

## 3. Языки снизу вверх

Слова считаются так: слово — то, что читает компилятор языка (имя или буква-команда); слово, записанное в двух текстах (`c` и `copy`), — одно. Не слова: `#`, знаки `: & [ ] " '`, числа, имена пользователя, `link`, `zero`, имена таблиц `add4 sub4 hex4`.

### 3.1. Язык 1 — строка (4 слова)

| Слово | Что делает |
|---|---|
| `r dl dh sl sh` | строка: копирует `[sl,sh)` в `[dl,dh)`; числа шестнадцатеричные, до 5 цифр |
| `w N` | ширина поля A в битах (до первой `r`) |
| `z N` | N нулевых бит |
| `s 0101` | сырые биты в порядке памяти, пробелы свободны |

В текстах языков 1 и 2 `#` — комментарий, но только целой строкой. Действие одно (`r`); `w`, `z`, `s` лишь говорят, как записать биты образа. Адресов и имён нет: слой там, где стоят его строки. **Компилятор** — зерно `seed` (программа цепочки): читает текст до нулевого байта, пишет образ; ошибка — `l1: bad text` / `bad count` / `bad end byte`.

Печать буквы `A` (A=8: позиций 250, stdin — 251 = `fb`, stdout — 252 = `fc`):

```l1
w 8
r 0 60 fb fb
z 20
r fc fc 40 48
r 0 40 48 88
s 01000001
z 18
```

Строка 2 — загрузка: 96 бит (`60`) из stdin на место. Строка 3 — второй NOP загрузочного слоя (32 нуля). Дальше снимок: слой 0 из двух строк (байт на позициях 64–71 уходит в stdout; переход копирует нули с позиции 72 в процессор — останов), байт `A` и добивка до 12 байт. Образ: `l1text.py -e < a.l1 > a.img`, запуск: `emulator -s 250 -p 2 < a.img` печатает `A`. В пространстве: `{ cat seed.img; cat a.l1; printf '\0'; } | emulator -s 65530 -p 7` даёт тот же образ.

### 3.2. Язык 2 — три числа, данные, метки (6 слов)

| Слово | Числовой текст | Текст с именами (3.3) | Что делает | Из чего сделано |
|---|---|---|---|---|
| copy | `c n d s` | `copy &d &s` | `n` бит из `s` в `d` | строка `r d d+n s s+n` (сумма — у компилятора) |
| data | `d n v` | `:имя data n v` | `n` бит со значением `v` | строки `s …` |
| метка | `:имя` | `:имя` перед словом | число — позиция текста в битах | числа в полях |
| начало | `o` | — | с этого места позиция 0 | — |
| shl, shr | — | `shl x r k`, `shr x r k` | `r` = `x`, сдвинутый на `k` бит (приходят нули) | копия с другим смещением и копия нулей |

Числа — hex или `&имя`, `&имя+k`. Строки языка 1 (`w r z s #`) проходят как есть; строки каналов и загрузки пишут как `r` (длины разные). Три числа вместо четырёх — около 25 % текста, но образ для эмулятора остаётся с четырьмя полями. **Компиляторы:** `l2c` — метка одна строчная буква, ссылка назад; `l2l` — имена из `a-z 0-9 _` (1–15 байт, до 1024), ссылки вперёд и назад; текст подаётся дважды (`текст 0 текст 0`, как `cat t t`): первая копия определяет метки, вторая пишется. Ошибки `l2: …` / `l2l: bad text` / `bad count` / `bad label`.

Печать `Hi` и перевода строки (A=10, `-s 1018 -p 4`):

```l2
w a
r 0 1c0 3fb 3fb
z 78
o
# слой 0: переход на слой 1 (он ниже)
:layer_0 c a0 0 &layer_1
z 78
# данные: буфер на 3 байта и числа-байты H, i, перевод строки
:buffer d 18 0
:byte_h d 8 12
:byte_i d 8 96
:byte_nl d 8 50
# слой 1: три копии в буфер и переход
:layer_1
c 8 &buffer &byte_h
c 8 &buffer+8 &byte_i
c 8 &buffer+10 &byte_nl
c a0 0 &layer_2
# слой 2: буфер в stdout, переход в NOP-слой — останов
:layer_2
r 3fc 3fc a0 b8
c a0 0 &image_end+50
:image_end
```

Запуск: `{ cat l2l.img; cat p.l2; printf '\0'; cat p.l2; printf '\0'; } | emulator -s 524282 -p 20 > p.l1`, затем `seed.img` на `p.l1` даёт образ.

### 3.3. Текст с именами (языки 2–4)

Файлы `*.tw`. Слова через пробелы и переводы строк, `#` — комментарий до конца строки.
- Числа десятичные (l3c: по модулю 2^20; Python ещё `0x…`), строки `"…"` с `\n \t \r \0 \\ \"` (Python ещё `\xNN`, `'c'`).
- Определяющее слово (`data table array block word stack`) стоит после метки `:имя`; больше метка нигде не нужна.
- Часть пространства: `&имя`, `&имя[k]` (бит), `&имя[lo:hi]`. Данные и таблицы объявляют вне блоков и до использования; блоки — в любом порядке; вход — блок `main`.
- Имена: `A-Za-z0-9_`, не с цифры (`l3c`: 1–14 байт; имена блоков и слов — только `a-z 0-9 _`). Готовые: `zero` (1 бит нуля, только чтение), таблицы `add4 sub4 hex4`.
- Текст читают слова не выше его языка; чужое слово — ошибка. Разбор — только по грамматике: Python пишет `строка:столбец: …`, `l3c` — `l3c: bad text / label / width / block`, `too big`.

### 3.4. Язык 3 — таблицы, блоки, вызовы (24 слова)

Слова со знаком † есть только в Python (`text.py`); `l3c` их не читает.

| Слово | Запись | Что делает | Из чего сделано |
|---|---|---|---|
| `table` | `:T table K w v…` | 2^K значений по w бит (K 1–10, w 1–64) | данные с шагом 2^j, выровнены |
| `array` | `:T array K w` | та же, но пишется; сначала нули | как `table` |
| `lut` | `lut &T i out` | `out` = T[i] | копия индекса в поля источника строки; строка копирует запись |
| `store` | `store &T i src` | T[i] = `src` | то же, поля назначения |
| `block` | `:b block` | начало блока | слои; конец — `goto if call ret halt` |
| `word` | `:w word` | вызываемый блок, одна ссылка возврата | блок и участок для ссылки (2A бит) |
| `goto` | `goto &b` | переход в блок | строка перехода копирует слой `b` |
| `if` | `if c &b1 &b0` | бит `c` = 1 → `b1`, иначе `b0` | таблица из двух ссылок и `lut` в строку перехода |
| `call` | `call &w &back` | вызвать `w`, вернуться в `back` | копия ссылки на `back` в возврат `w`, `goto w` |
| `ret` | `ret` | вернуться из слова | копия возврата в строку перехода |
| `halt` | `halt` | остановить | переход в слой из NOP |
| `emit` | `emit s` | `s` в stdout (целые байты) | строка с назначением `S+2` |
| `warn` | `warn s` | `s` в stderr | назначение `S+3` |
| `key` | `key d` | байт из stdin в `d` | строка с источником `S+1` |
| `add` | `add x y r` | `r` = x+y; x, y — целое число ниббл (4 бит), `r` на бит больше (перенос) | цепочка `lut` по `add4` |
| `sub` | `sub x y r` | `r` = x−y по модулю; старший бит `r` = 1, если x<y | по `sub4` |
| `band` | `band x y r` | `r` = x и y (та же ширина) | по `and4` |
| `lt` | `lt x y r` | бит `r[n]` = 1, если x<y (n — число нибблов, `r` не короче n+1) | по `lt4c` |
| `eq` | `eq x y r` | последний бит `r` (n бит) = 1, если x=y | по `eq4c` |
| `stack`† | `:s stack K w` | стек: 2^K записей и указатель | `array`, таблицы `inc`, `dec` |
| `push`† | `push &s src` | положить | `store`, `lut` |
| `pop`† | `pop &s dst` | снять | `lut`, `lut` |
| `rec`† | `rec &w &s` | `w` рекурсивно: возврат — в стек | `call`/`ret` через `push`/`pop` |
| `pack` | `pack` (первое слово) | режим упаковки: P=3, в слое до двух строк | `l3c` пишет серийно, `l3p` упаковывает |

Слова языка 2 (`data copy shl shr`) пишутся здесь же. Слова языка 3 берут нижние: по замеру `lut` с одним индексом — 3 строки в 4 слоях, `if` — 3 строки в 6.

**Компиляторы:** `l3c` (текст → текст языка 2 с метками, серийная раскладка: строка = слой, A=20, P=2) и проход `l3p` (после `pack`: до двух строк в слое, P=3). Цепочка: текст → `l3c` → `l2l` → `seed` → образ; с упаковкой: `l3c` → `l3p` → `l2l` → `seed`; с адресом хоста в `copy` проход `l4c` стоит перед `l3c` (3.5). В Python `text.py` собирает образ сразу (наименьшее A).

Если 3 < 9, печатает `Y`, иначе `N`:

```tw
:a data 8 3
:b data 8 9
:c data 3 0             # результат lt: 3 бита (n=2 ниббла, нужно n+1)
:y data 8 "Y"
:n data 8 "N"
:main block
lt &a &b &c
if &c[2] &yes &no
:yes block
emit &y
halt
:no block
emit &n
halt
```

Таблица и `lut`: печатает `C` и перевод строки (запись 2):

```tw
:ch table 2 8 "A" "B" "C" "D"
:i data 2 2
:o data 8 0
:nl data 8 "\n"
:main block
lut &ch &i &o
emit &o
emit &nl
halt
```

Слово, вызванное из двух мест (`Hi`):

```tw
:hi data 16 "Hi"
:nl data 8 "\n"
:out data 8 0
:main block
copy &out &hi[0:8]
call &show &m1
:m1 block
copy &out &hi[8:16]
call &show &m2
:m2 block
emit &nl
halt
:show word
emit &out
ret
```

Цикл: читает stdin до нулевого байта и печатает его (`echo`):

```tw
:b data 8 0
:z data 8 0
:c data 2 0
:main block
goto &loop
:loop block
key &b
eq &b &z &c
if &c[1] &done &out
:out block
emit &b
goto &loop
:done block
halt
```

Запуск в Python: `python3 -B -m tower.text < p.tw > p.img` (A и P — в stderr), затем `emulator -s 2^A-6 -p P < p.img`. По цепочке: раздел 8.

### 3.5. Язык 4 — адреса в копировании (слов нет)

У языка 4 нет своих слов: текст языка 4 — текст языка 3, в котором у `copy` адрес может быть трёх форм: **адрес хоста** (`0x1…`), **дальний адрес** (`0x2…`, опыт, см. словарь) и **канал от конца** `+k`; проход `l4c` переводит их в обычные `copy`. Слой языка сам по адресу берёт определение копирования: адрес меньше S — пространство; от S до 2^A − 1 — канал (строка с `dl=dh=C` или `sl=sh=C`, как у `emit` и `key`; в `copy` канал — десятичное число или `+k`); от 2^A и выше — позиция в адресном пространстве хоста; это определение длинное: запрос SYS, собранный копированиями (`l4c`). Для `+k` `l4c` подставляет число для A = 20: цепочка собирает образы только для A = 20.

Адрес хоста в тексте — число `0x1` и 32 шестнадцатеричные цифры: 2^128 плюс позиция `pos` = область · 2^96 + бит (старшие 32 бита — область: 0 — часы, 64 бита; 1, 2… — файлы `-r путь`; младшие 96 — бит в области). Это постоянная текста (адрес, вычисляемый при работе, пока не делается). Запись выбрана исполнителем и легко меняется (проход читает её одним местом). Ошибок нет: вне файла читаются нули, запись пропадает.

**Канал `+k`** (k = 0…5) — конец пространства плюс k: `+0` SYS, `+1` stdin, `+2` stdout, `+3` stderr, `+4` и `+5` — fd 3 и 4; `l4c` переводит его в число S+k (число умеет `l3c`), длина — от другой стороны.

**Компилятор** — проход `l4c` (`programs/l4c.tw`, программа цепочки) над текстом языка 3: текст идёт как есть, а `copy &x <адрес>` (чтение) и `copy <адрес> &x` (запись) он заменяет копированиями языка 3: буфер запроса `l4q` (204 + 2048 бит) и константы `l4z`, `l4n0`…`l4n3` объявлены в начале текста (после слова `pack`, если оно первое); заголовок запроса (op, chan, flags, arg, off) и данные собираются копированиями из этих констант, запрос уходит копированием в канал `1048570` (S), ответ читается копированием из него. Длину `n` даёт часть `&x[lo:hi]`, `&x[k]` или `&x` целиком (проход помнит ширины `:имя data n …`); при `n` не от 1 до 2048, неизвестной ширине или двух адресах хоста копирование идёт дальше как было, и `l3c` его отвергает. Цепочка: текст → `l4c` → `l3c` → [`l3p`] → `l2l` → `seed`; тексту без адреса хоста проход не нужен. Пишет `hello` на бит 8 области 1 и читает обратно (файл `f.bin` не короче 2 байт; цепочка, A=20: `emulator -s 1048570 -p 2 -r f.bin < p.img` печатает `hello`):

```tw
:out data 40 "hello"
:got data 40 "\0\0\0\0\0"
:main block
copy 0x100000001000000000000000000000008 &out
copy &got 0x100000001000000000000000000000008
emit &got
halt
```

**Дальний адрес** (опыт, см. словарь) — число `0x2` и 32 шестнадцатеричные цифры: звено (старшие 32 бита; 0 — сосед по stdin/stdout) и позиция в дальнем пространстве (младшие 96 бит). Это тоже `copy`, новых слов нет: какое определение применить, язык выбирает по адресу.
`copy &x 0x2…` и `copy 0x2… &x` проход `l4c` переводит в запросы соседу по одному байту; запись запроса — 6 байт: op 8 бит (0 — останов, 1 — get, 2 — put), номер байта 32 бита (= позиция / 8), данные 8 бит; get отвечает байтом (вне окна ответчика — единицы), put ответа не даёт (ответчик `programs/far/far_serve.tw`, пример `far_copy.tw`).
Запрос уходит `emit`, ответ читается `key` уже в следующем блоке (после `goto`: раскладка не упорядочивает строки разных устройств, иначе взаимная блокировка). Переводится при звене 0, позиции, кратной 8 бит и меньшей 2^32, ширине `&x` от 8 до 64 бит целыми байтами; всё остальное идёт дальше как было (`l3c` отвергает), как адрес хоста — никогда; есть и технические пределы (нижняя граница среза меньше 9900, не больше 2048 порождённых меток), за ними тоже отвергает `l3c`; `0x2` с другим числом цифр — по-прежнему адрес хоста. При отказе дальнего копирования (нет ответчика, закрытый канал, выход за окно) запрашивающий получает единицы, неотличимые от данных 0xFF; вариант с проверкой `l4c` не переводит. Если дальний адрес не переводится, `l4c` пишет причину в stderr одной строкой: `l4c: far link` (звено не 0), `far pos` (позиция не кратна 8 бит или от 2^32), `far width` (ширина не 8…64 бит целыми байтами или операнд не найден), `far limit` (технический предел). Такты и размеры образов — в [замерах](../docs/measurements/tower.md).

Второе определение того же копирования (26.5, 26.6; опыты `programs/far/`, написаны вручную, `l4c` их не переводит): общий файл `-r path` у двух эмуляторов — `far_file_a.tw` пишет данные `copy 0x1… &v`, затем флаг готовности; `far_file_b.tw` опрашивает флаг копированием из файла в цикле (счётчик `add`, `lt`; адрес — постоянная текста) и только после флага читает данные; не пришёл за `limit` опросов — данные из одних единиц. Проверочный протокол — `far_serve_ck.tw` / `far_get_ck.tw`: запрос 7 байт с суммой, ответ 2 байта (значение и дополнение до 255), при несовпадении до 4 повторов, потом единицы.

### 3.6. Язык 5 — цена (3 слова, только Python)

Не текст, а вызовы над готовым результатом нижних языков (нижние о цене не знают):

| Слово | Что делает |
|---|---|
| `cost p` | `(rows, layers, bits, ticks)`: строки и слои хранимого текста, его биты, слои, выполненные по пути |
| `price c` | одно число: 32·rows + 32·layers + bits + 64·ticks; 2^24, если путь запретителен |
| `replace d1 d2 …` | из определений с одинаковым результатом на проверочных входах — дешевле |

Путь с неизвестным числом проходов (цикл по данным) стоит 2^24, пока не задано `passes`. `chain_cost` и `replace_layout` — те же слова для программы цепочки (серийная или `pack`). Пример (программа «3 < 9» выше):

```py
import text, l5           # запуск из каталога tower/; branch.tw — пример выше
p, errors = text.compile_text(open('branch.tw').read())
c = l5.cost(p)            # Cost(rows=35, layers=12, bits=1968, ticks=13)
l5.price(c)               # 4304 = 32*35 + 32*12 + 1968 + 64*13
```

### 3.7. Форт (64 слова, программа цепочки)

Компилятор подмножества Форта `programs/forth.tw` — обычная программа на языке 3, новых слов в языках 1–3 нет. Он читает текст Форта со stdin до нулевого байта и пишет текст языка 3 (и нулевой байт); дальше та же цепочка: Форт → `forth` → `l3c` → `l2l` → `seed` → образ. Один проход: слово определено до использования, код определения пишется, как только оно прочитано, текст целиком не хранится. Имя слова различают по последним 8 знакам, неизвестное слово пропускается (ошибок нет), `s"` — до 32 байт.

| Слова | |
|---|---|
| стек | `dup drop swap over rot pick roll >r r> r@ i j unloop` |
| арифметика, 32 бита | `+ - * / mod /mod and or xor lshift rshift` `1+ 1- 2* cell+ cells`; сдвиг на ≥ 32 даёт 0; деление на 0 — останов |
| сравнения (истина −1) | `= < u< 0=` |
| память (1024 байта, адрес по модулю 1024) | `@ ! c@ c! variable constant create allot s" [char]` |
| управление | `: ; if else then begin until while repeat do ?do loop leave exit recurse execute ' [']` |
| прочее | `emit ( \ decimal` |

Как компилируется:
- Стек данных и стек возвратов — массивы с указателем в 6 бит (непересечение построением, раздел 5); число — именованный участок `data 32` (данные вне блока, поэтому литерал разрезает блок `goto`); `if`, `begin`, `do` — блоки и `if`.
- Вызов слова — код места возврата на стек возвратов и `goto`; `;` и `exit` снимают код и находят место деревом `if` по его битам (пишется в конце, `execute` — таким же деревом по номеру слова). Поэтому `recurse` — тот же вызов.
- `* / mod /mod lshift rshift @ ! c@ c! pick roll + - and or xor = < u<` — подпрограммы: слова языка 3 (`call`, `ret`), каждая пишется в конце один раз, если слово использовано. Их текст и тексты остального кода — шаблоны в `programs/forth.def`; программа цепочки `forthgen` (23.16) делает из них таблицы `forth.tw` между метками `generated`.
- Стеки (`lut` по таблицам `inc`/`dec` и `store`) и возврат (код и дерево `if`) сделаны заново: те же действия — слова `stack push pop rec`, но они только в Python-эталоне, а в `l3c` не помещаются (до границы A=20 свободно 1 996 Б из 128 000). Решение автора: добавить их в `l3c` при A=21 или принять как есть.
- Код вне определений исполняется при старте; в конце вызывается `main`, если он определён.

Пример (`: sq dup * ; 5 sq 48 + emit` печатает `I`) — выход `forth`: `:w0 block` (`sq`), строки `dup`, `call &f11 &b1` (`*`), `:b1 block`, `goto &rt`; `5` — `goto &b2`, `:l2 data 32 5`, `:b2 block`, `store &ds &sp &l2`, `lut &inc &sp &sp`; вызов `sq` — `store &rs &rp &c0`, `lut &inc &rp &rp`, `goto &w0`, `:k0 block`; в конце — `:f1 word` (`+`), `:f11 word` (`*`), `:rt block` и дерево `:n1 block`, `if &rc[0] &kz &k0`.

## 5. Непересечение (7.2.33)

В цепочке непересечение данных — **построение**, а не доказательство.
- Адреса `copy` известны компилятору. Ссылка `&имя[lo:hi]` вне данных имени — `l3c: bad width`.
- `store` и вычисляемый адрес берут индекс из k бит: выйти из массива на 2^k записей он не может.
- Каждое имя получает свой участок от распределителя (`Alloc` в `common.py`); общие участки (`zeros`, `one`, пара ссылок с одним значением) — лишь для чтения.
- Планировщик не кладёт в один такт строки с общими битами. Гарантируется: данные и записи слоёв не накладываются, если компилятор верен.
- Не гарантируется: верность самого компилятора и значения, записанные в индекс шире k бит (обрезаются по модулю 2^k).
- `checked` эмулятора и аудит `intervals` (`tests/test_tower.py`) — проверка, не часть определения. Нынешний язык берёт `dj-prove`: доказывает непересечение слоёв программы до запуска; здесь доказывать нечего — оно в построении.

## 6. Что работает в пространстве, что пока на хосте

**В пространстве** (эмулятор на C, Python на пути нет): `seed` (язык 1 → образ, 8 028 Б), `l2c` (20 228 Б), `l2l` (59 937 Б), `l3c` (127 028 Б), `l3p` (117 812 Б), `l4c` (76 564 Б), `forth` (92 468 Б) — программы `programs/*.tw` на языках 1–3. Неподвижные точки: `seed.img` на `seed.l1` даёт себя; `l3c`, собранный из `l3c.tw`, даёт тот же `l3c.l1` и тот же образ побайтно; так же `l3c` с `pack` и `l3p`. Язык 4 работает: `l4c → l3c → [l3p] → l2l → seed` даёт образ, который делает длинное копирование как образ Python (вывод и файл хоста те же). Этой цепочкой собраны 37 программ нынешнего языка: вручную на языке 3 (23.11, `programs/forth37/*.tw`) и из текстов Форта (23.15, `forth37/*.fs`), 37 из 37, вывод один и тот же; у `bytes` верно `0ABC0` (сдвиг на ≥ 32 даёт 0, нынешний язык берёт его по модулю 32 и печатает `6` — это его ошибка). Для `forth` Python не нужен: `forth.l1` — выход `l3c → l2l`, таблицы делает `forthgen` (`programs/forthgen.tw`, 96 052 Б, 6,9 млн тактов). Пределы `l3c`: A=20 (занято 127 008 Б из 128 000), канал в `copy` — число от S, данные длинного копирования (`l4c`) до 2048 бит, имён пользователя 1020 (проход `l4c`: имён `data` 63, у Python-эталона `l3ctext.py` 1024), меток `l2l` 1024, таблиц и массивов до 2^10 записей, строк до 32 байт.

**Пока на хосте (Python):**
- Эталоны инструментов `l1text.py`, `l2text.py`, `l2ltext.py`, `l3ctext.py`: тесты сверяют их с образами побайтно.
- Первый `seed.img` (`l1text.py -e` на `seed.l1`) и тексты языка 1 `seed.l1`, `l2c.l1`, `l2l.l1`, `l3c.l1`: их один раз создал Python, цепочка воспроизводит; после правки `seed.tw`, `l2l.tw`, `l3c.tw` их пересоздают (раздел 8).
- Язык 5, слова `stack push pop rec`, `dec<n>`, `0x`, `'c'`: `l5.py`, `lib.py`, `text.py`; `l3c` их не знает. Язык 4 для Python-построителя (адрес хоста в `copy` читает `text.py`) — `l4.py`.
- Построитель `l3.py` (наименьшее A, упаковка слоёв) и разбор `text.py` с сообщениями `строка:столбец`.
- Тесты и замеры (`unittest`, `measure.py`). Эмулятор — программа на C на хосте; режим `checked` проверяет непересечение.

Не сделано в `l3p`: прямая запись в процессор (`lut` остаётся в 4 слоях, `if` в 6), окно 8 строк, 3 слота.

## 7. Минимум понятий — черновик для автора (23.14, решает автор)

«Необходимо» — без понятия нельзя получить вычисление или запустить его; «удобство» — выводится из остальных или лишь облегчает текст.

| Понятие | Пометка | Почему |
|---|---|---|
| бит, пространство, позиция, полуинтервал | необходимо | всё хранится и адресуется ими |
| копирование, строка из четырёх чисел | необходимо | единственное действие и его запись |
| NOP | необходимо | заполняет пустые строки; процессор из NOP — останов |
| процессор — часть пространства | необходимо | иначе строки не переписать: ни перехода, ни косвенности |
| такт, слой | необходимо | одновременность; «записанное видно со следующего такта» |
| переход = копия слоя в процессор | необходимо | единственное управление |
| непересечение (построением) | необходимо | иначе результат зависит от порядка строк |
| порядок бит | необходимо | соглашение: число и байт иначе не сравнить |
| образ, загрузочная строка | необходимо | как начальные биты попадают в пространство |
| каналы stdin, stdout | необходимо | вход и выход программы |
| канал stderr, `warn` | удобство | сообщение об ошибке можно слать в stdout |
| SYS, язык 4 | необходимо для хоста | для самого вычисления не нужны |
| косвенность, таблица, `lut` | необходимо | единственный доступ по вычисляемому адресу; сумма и сравнение — таблицы |
| выравнивание, шаг 2^j | необходимо | иначе конец записи переносится в индекс |
| `array`, `store` | необходимо | запись по вычисляемому адресу: стек, память, словарь |
| вычисляемый переход (`if`) | необходимо | единственное ветвление: таблица из двух ссылок |
| блок, `halt` | необходимо | точка перехода и останов; имя блока — удобство |
| `word`, `call`, `ret` | удобство | ссылка возврата + `goto`; нужны как слова, потому что текст не называет строку перехода |
| `emit`, `key` | удобство | строки каналов языка 1 с готовыми аргументами |
| три числа в `copy` (язык 2) | удобство | короче текст на 25 %, образ тот же |
| `data` с начальным значением | необходимо | начальные биты образа |
| `w` | необходимо | в образе нет заголовка, ширину A знает только кодер |
| `z`, `#`, `o` | удобство текста | `z` — сокращённое `s`; `o` — отсчёт позиций от снимка |
| метки, `&имя`, ссылки вперёд (два прохода) | удобство текста | позиции мог бы считать автор |
| имена, срезы `[lo:hi]`, числа десятичные, строки | удобство текста | в образе их нет |
| распределитель, раскладка данных | удобство текста | адреса мог бы назначить автор (кроме выравнивания) |
| проверка текста при разборе | удобство | ошибок в языке нет; нижние языки не проверяют |
| `add sub band lt eq`, `shl shr` | удобство | цепочки `lut` и копии; в 37 программах умножение и деление написаны в тексте |
| `stack push pop rec` | удобство | массив и указатель; в `l3c` их нет, 37 программ обошлись |
| `pack`, `l3p` | удобство | сжимает слои; результат тот же |
| цена (язык 5) | удобство | исполнению не нужна; выбор определения |
| зерно, самосборка | необходимо | с чего начинается; неподвижная точка — проверка |

## 8. Сборка и проверка

    { cat l2l.img; cat prog.l2; cat prog.l2; } | $E -s 524282 -p 20 > prog.l1
    { cat seed.img; cat prog.l1; } | $E -s 65530 -p 7 > prog.img; $E -s 1048570 -p 2 < prog.img
