# Исходный выпуск vm2

Основной путь — сохранённый прямой ABI `vm2-direct-v1` и запускатель vm2c.
Совместимый интерпретатор vm2 сохраняет прежний формат троек и SYS.
space остаётся только явным legacy-контролем. См. [direct.md](direct.md).

`make dist` создаёт dist/vm2-VERSION.tar.gz и внешний SHA256. Включаются
только файлы dist.manifest и явно объявленные исходные зависимости vm1/copycode
по их манифестам. Снимки содержатся в vendor/, происхождение и хеши —
VENDORED.json, SHA256SUMS покрывает весь архив. Это позволяет проверить
релиз без соседних каталогов и без сетевой загрузки. Генерируемые build/tmp
и результаты эмуляции в исходный архив не входят. SOURCE_DATE_EPOCH по
умолчанию 0; одинаковые исходники/эпоха дают побайтно одинаковый архив.

`make distcheck` распаковывает комплект в новый путь с пробелами, собирает
vm1 из вложенных исходников, выполняет полный гостевой набор, независимые
C-контроли, установку, настоящий запуск установленного vm2 и проверяет
побайтное совпадение повторного архива после всех операций. Проверяет clean.

```sh
make install prefix=/usr/local
make install prefix=/usr DESTDIR=/tmp/vm2-package
```

Устанавливаются bin/{vm2c,vm2}, libexec/vm2/{vm2compile,vm2guest,copycode}, документация и
MIT/Apache-2.0 лицензии. Ядро vm1 устанавливается отдельно либо задаётся
через VM1. bindir/libdir/docdir можно менять; пути должны быть абсолютными.
Относительный путь запускателя к Python-модулям сохраняет работу DESTDIR
и переносимого промежуточного каталога. Legacy C, проверочный аудитор и
тестовые модули не устанавливаются. Сам make install код гостя не исполняет.
