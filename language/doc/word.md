# Запись слова: механизмы (14.11)

Слово языка — механизм. Его механизмы хранит запись словаря компилятора: понятие (имя, ячейка
понятия), определения по типам адресации, цена, доказательство, стек определений. Запись делает
`fc-define` (`src/forthc.fth`), механизмы заполняет `fc-mechanisms`, цену — `;` (`fc-price-word`).

## Запись: 16 ячеек

| Ячейка | Механизм | Что хранит |
|---|---|---|
| 0, 1 | понятие: имя | смещение имени в области имён и длина |
| 2 | вид | 0 — данные или константа, 1 — слово, бит 2 — генератор (как в 14.3) |
| 3 | понятие: ячейка понятия | у слова — xt текущего определения (вход в индексном пространстве); у данных — значение, у генератора — его xt |
| 4 | — | следующая запись цепочки имени |
| 5 | понятие | адрес ячейки понятия, через которую вызывается слово; у нового слова — своя ячейка 3, у синонима (14.13) — ячейка 3 исходного слова |
| 6 | определение: индексное пространство | вход определения (ячейка первого слоя) |
| 7, 8 | определение: копи- и хост пространство | 0 — нет; в ячейке 8 у определения `host` (15.3) — номер программы хоста + 1, его платформа 1 (`doc/platform.md`) |
| 9 | цена: размер | ячейки слоёв определения — точно |
| 10, 11, 12 | цена: биты, копирования, слои | наибольшего пути исполнения, если известны при компиляции |
| 13 | цена: признак | -1 — известна при компиляции, 0 — по исполнению (тогда 10–12 нули) |
| 14 | доказательство | `fc-proved` — ссылка на общее слово «доказано»; иначе адрес записи недоказанного |
| 15 | стек определений | прежние определения; 0 — пуст (заполнит замена, 14.13) |

**Вызов слова — через ячейку понятия.** Компилятор берёт xt из ячейки понятия (`fc-xt`: ячейка 5 →
адрес → содержимое) при каждом вызове слова (`fc-word-token`), в `[']` (`gen-tick`), `recurse` и
при вызове `main`. В индексном пространстве вызов — переход на этот xt, скомпилированный в момент
компиляции вызова: в коде нет лишнего косвенного шага, потоки 37 программ прежние. Если ячейка
понятия получает другой xt, все вызовы, скомпилированные после этого, идут в новое определение
(проверено в `tests/test_word.py`: генератор `rebind a b` кладёт xt `b` в ячейку понятия `a`, и
`a` и `['] a execute` исполняют `b`); уже скомпилированный код меняется перекомпиляцией (14.14).

**Доказательство.** Общее слово «доказано» — `fc-proved`: таблица из одного однобитного значения 1
(одна ячейка со значением 1). Запись недоказанного — `fc-unproved`: число проверенных входов, их
биты, способ (0 0 0 — ничего не проверено); на неё ссылается каждая новая запись. Пока ни одно слово
не доказано. Проверка таблицей (14.12) идёт при исполнении программы, поэтому её результат хранит не
запись компилятора, а реестр доказательств в памяти программы с копией слова «доказано» (`doc/proof.md`).

## Слова

| Слово | Где | Что делает |
|---|---|---|
| cost ( xt -- size bits copies layers known ) | язык, генератор `gen-cost` | цена слова; xt — литерал, известный при компиляции (`['] w cost`), иначе -13; xt не слова — 0 0 0 0 0. Компилирует пять литералов |
| price ( size bits copies layers -- n ) | язык, генератор `gen-price` | начальная формула — сумма: три `+` (на верхнем уровне свёртка известных значений). Заменяемо, как любое имя генератора |
| proved? ( xt -- f ) | язык, генератор `gen-proved?` | истина, если доказательство — ссылка на `fc-proved`; xt — как у cost |
| `fc-cost`, `fc-proved?`, `fc-word-of` | компилятор | то же по xt; `fc-word-of` — самая новая запись слова, ячейка понятия которой содержит xt |

Определению языка cost, price, proved? не нужны: их имена не входят в ядро (`doc/core.md`, «не
использованы»), записей в `doc/language.md` у них нет, а генераторы `gen-cost`, `gen-price`,
`gen-proved?` — слова ядра с записями.

## Цена при компиляции

**Размер** — ячейки от входа слова до первой свободной ячейки после его `;` (`lay-next-cell`): все
ячейки его слоёв, включая ячейки групп ветвлений, которые слою не достались. Ячейка выравнивания
перед входом (группа входа — две ячейки) в размер не входит. Размер точен у любого слова.

**Биты, копирования, слои** — на пути исполнения от входа слова до батута его возврата
включительно (батут — слой без строк, кроме строки связи). Пролог вызова (сброс кэша стека, адрес
возврата на стек возвратов) — в слоях вызывающего. За слой:

- слои — 1;
- копирования — строки с n > 0, включая строку связи (каждый слой копирует следующий в процессор);
- биты — n копирований между позициями пространства, строка связи — 1024 бита; копирования канала
  (`emit`, `key`) — копирования, но не биты (как в 13.4: биты канала — `channel_bits`).

Ширина строки, поля которой вписываются при исполнении (приёмник `space!`, источник `space@`), —
ширина её другой пары полей.

**Как найдено.** Пока компилируется слово, каждый записываемый слой (`lay-write` →
`lay-on-write` → `fc-log-layer`) идёт в журнал: ячейка, копирования, биты, следующая ячейка.
Генераторы отмечают слои-решения (`fc-log-decision`: `if`, `while`, проверка адреса `@ ! c@ c!`,
`throw`; цели — 2^k ячеек с шагом ветвления от следующей) и вызовы (`fc-log-call`: ячейка
продолжения и цена вызываемого — слова из его записи, подпрограммы `*` `/` из `fc-mul-cost`,
`fc-div-cost`). `fc-path` идёт по журналу: слои записаны в порядке создания, путь слова без
циклов идёт только к более поздним слоям, поэтому один проход даёт наибольший путь — сумма по
слоям и вызовам, при ветвлении наибольшая ветвь, отдельно для каждого счётчика. Путь в `fc-thrower`
(`throw`, ошибка адреса, деление на ноль) покидает слово и не считается.

**По исполнению** (признак 0, биты, копирования и слои 0): `begin`, `do`, `?do` (цикл), `recurse`,
`execute`, `catch` (вызов xt) — генератор сразу кончает журнал (`fc-by-execution`); вызов слова,
цена которого по исполнению; переполнение журнала (2048 слоёв, 64 отметки). Независимо от этого
`fc-path` даёт «по исполнению», если осталась цель, до которой не дошёл ни один слой (возврат
назад, переход вне слова), или отметки не совпали со слоями.

**Подпрограммы `*` и `/`** строятся до кода программы, их последние слои ещё не записаны
(записать раньше — изменить порядок потока): `fc-helpers-cost` пишет их в журнал как есть и
находит путь от входа до выхода. Умножение: 77 слоёв, 503 копирования, 80 770 бит; деление: 751
слой, 4109 копирований, 783 414 бит.

Поток не меняется: журнал только читает записи слоёв, отметки и анализ не создают ни ячеек, ни
констант. `check-programs STREAMS=equal`: потоки 37 программ побайтно равны потокам модели.

## Сверка со счётчиками 13.4

`language/tests/reference/vm2_reference.py` (функция `run`) исполняет трёхпольные образы vm2 (строка
[n, dst, src] из 3A−1 бит, не больше 1000 тактов, полная копия памяти на такт). Поток языка —
четырёхиндексный (контракт emulator: [dst_low, dst_high, src_low, src_high], S = 2^31): `run` его
исполнить не может. Поэтому `tools/counters.py` — та же машина для четырёхиндексных строк: битовые
функции `vm2_reference` (`get`, `put`, `payload`, `store_bytes`) на разреженной памяти, все
источники такта читаются до записей, и на каждом такте счётчики по определениям 13.4, как их считает
`run`: `layers` — такты; `copies` — инструкции с n > 0, которые изменили память или передали байт
через канал; `bits` — n копирований память–память; `channel_bits`. Ещё он считает `rows` —
исполненные инструкции с n > 0 (изменили память или нет). Ячейка такта — цель строки связи
предыдущего такта; исполнение слова — от первого такта на его входе до такта батута его возврата
(вложенные вызовы учитываются по глубине).

Программа `tests/test_word.py` (вывод `A`), на хосте, 1685 тактов; пять слов без циклов:

| Слово | Что | Размер | Цена: слои | Такты (13.4) | Биты | Биты (13.4) | Копирования | Исполнено инструкций | Копирования (13.4) |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `w1` | `+ 2*` | 53 | 53 | 53 | 55 118 | 55 118 | 143 | 143 | 80 |
| `w2` | `dup 0= if 1+ else 1- 1- then` | 165 | 120 | 120 | 124 344 | 124 344 | 307 | 307 | 209 |
| `w3` | `dup @ 1+ swap !` | 74 | 68 | 68 | 70 482 | 70 482 | 173 | 173 | 94 |
| `w4` | `3 4 w1 drop 65 emit` | 38 | 91 | 91 | 94 854 | 94 854 | 224 | 224 | 144 |
| `w5` | `over over * >r / r>` | 45 | 873 | 873 | 911 576 | 911 576 | 4722 | 4722 | 1812 |

- Слои и биты цены **равны** счётчикам 13.4 на исполнении; копирования цены равны исполненным
  инструкциям; копирования 13.4 (только изменившие память) меньше: 54–68 % у простых слов, 38 % у
  `w5` (подпрограммы много раз пишут в память те же биты).
- `w2` исполнен на обеих ветвях: 94 слоя и 97 498 бит (`1+`), 120 и 124 344 (`1- 1-`); цена —
  наибольшая ветвь, она равна исполнению длинной ветви.
- `w4` — вызов слова и канал: сумма по вызовам (53 слоя `w1` внутри 91), `emit` — копирование без
  бит; `w5` — вызовы подпрограмм умножения и деления, их цена — 828 из 873 слоёв.
- Размер: такты каждого слова — в его ячейках (кроме вызванных, подпрограмм и батута), ячейки слов
  идут подряд, между ними не больше одной ячейки выравнивания.

Ядро L0 на emulator даёт программе, которую компилирует, те же цены и одну метку входа изоляции
(14.10: копия 32 нулевых бит в первом слое слова): `w1` — 144 копирования и 55 150 бит против 143 и
55 118 на хосте, размер и слои те же.

## Цена слов определения языка

Когда хост компилирует определение (бут), цену получает каждое его слово: 441 имя, у 182 цена
известна при компиляции, у 259 — по исполнению (циклы, рекурсия, вызов xt и вызовы таких слов).
Известные: размер 11–648 ячеек (медиана 70), слои 11–1607 (медиана 91), биты 11 456 – 1 667 778.
`tools/word_cost.py` печатает таблицу (`python3 -B language/tools/word_cost.py [FILE]`).

В `doc/language.md` цена записи определения `:` — цена компилятора: «размер N яч., биты B,
копирования C, слои L (при компиляции)» или «размер N яч.; биты, копирования, слои — по
исполнению». Её пишет `tools/language_md.py --prices`, `tests/test_word.py` проверяет равенство;
после изменения определения нужно запустить `--prices` (иначе `make check` не проходит).

## Решения исполнителя (автор может изменить)

1. **Сверка не через `vm2_reference.run`.** Он исполняет только трёхпольные образы vm2; поток
   языка четырёхиндексный. `tools/counters.py` берёт его битовые функции и определения счётчиков
   13.4 и исполняет четырёхиндексные строки (реализация машины — по контракту emulator и оракулу
   `copycode/tests/test_vm1.py`).
2. **Копирования цены — исполненные инструкции с n > 0** (вместе со строкой связи). Копирования
   13.4 считают только изменившие память; это зависит от данных и при компиляции неизвестно. Цена —
   верхняя граница копирований 13.4.
3. **Биты — с строкой связи** (1024 на слой), без бит канала — как `bits` 13.4.
4. **Граница слова** — от входа до батута возврата включительно; пролог вызова — у вызывающего.
5. **Бросок не считается**: путь в `fc-thrower` (`throw`, ошибка адреса, деление на ноль) кончается
   вне слова, цену дальше определяет обработчик.
6. **Наибольшая ветвь — по каждому счётчику отдельно.** Если у ветвей разные «наибольшие» счётчики,
   цена — не цена одного пути, а верхняя граница каждого.
7. **Вызов через ячейку понятия — при компиляции**, без косвенного шага при исполнении (такт
   дороже на каждом вызове и другие потоки). Замена определения влияет на вызовы, скомпилированные
   после неё.
8. **cost и proved? — только для xt, известного при компиляции** (литерал), как `pick`/`roll`; xt
   на стеке при исполнении даёт -13. Таблицы цен в пространстве программы нет.
9. **price — генератор** (три `+`), а не определение `:`: программе пользователя доступны только
   генераторы и её слова. Формула в одном месте — `gen-price`.
10. **«Доказано» — данные компилятора `fc-proved`**, а не имя в словаре программы; запись
    недоказанного общая (`fc-unproved`), пока ничего не проверяется.
11. **Размер — диапазон ячеек**, а не число слоёв: ячейки групп ветвлений, не занятые слоями, тоже
    принадлежат слову.
12. **Цены в `doc/language.md` — из компилятора** (`--prices`), проверяет их `test_word.py`, а не
    `check-language-md` (тому нужен бут). У переменных, констант, данных, генераторов и цифр цена —
    по-прежнему словами.
13. `test_word.py` добавлен в `check-tests` (`make check`).

## Что не закрыто

- Цена «по исполнению» не измеряется во время исполнения (стоп-слово отложено до решения автора).
- Стек определений, синонимы, `replace` — с 14.13 (`doc/replace.md`): синоним — запись на ячейку
  понятия исходного слова, замена и стек определений — при исполнении, в таблице слов программы;
  ячейка 15 записи компилятора по-прежнему 0. Копи- и хост пространство — пустые поля.
- Доказательство — поля, `fc-proved`, `fc-unproved` и proved? (с 14.12 проверки таблицами —
  `doc/proof.md`; записи компилятора они не меняют).
- Копирования 13.4 (изменившие память) при компиляции не находятся.
- cost по xt, известному только при исполнении, не поддержан.
