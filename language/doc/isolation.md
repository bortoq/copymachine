# Изоляция ядра: динамическая изоляция и слово непересечения (14.10, 18.18)

Ядро L0 лежит в верхней половине пространства: код с ячейки 2^19 (бит 2^29) и данные с бита
3·2^29, то есть блоки по 2^29 бит номер 1 и 3. Программа, которую оно компилирует, — в нижней
половине: блоки 0 (код) и 2 (данные). Изоляция — свойство построения кода языком (7.2.22 журнала
дизайна): в копипространстве исполняются только копирования, которые расставил язык; нарушить
изоляцию может только неверно написанный язык. Проверок при исполнении нет (14.10 их вводило,
18.18 убрало).

## Динамическая изоляция

Позиция копирования, которую программа вычисляет при исполнении, вписывается в строку слоем
раньше; в программе ядра (`fc-guard` не ноль, его ставит `kn-compile`) вписываются только
младшие биты позиции, а старшие — постоянная строки, которую пишет компилятор. Ядро и компилятор
как программа (`fc-guard` ноль) вписывают все биты: ядро само пишет всё пространство.

Раскладка записана в одном месте, в начале `forthc.fth`: `fc-bbits` (29 бит адреса в блоке),
`fc-abits` (28: область данных), `fc-ebits` (11: номер слова), `fc-etab` (таблица входов), `fc-rbits` (13: номер точки возврата), `fc-rtab`
(таблица возвратов).

| Слово | В программе ядра в строку вписывается |
|---|---|
| `space! spacec!` ( x lo -- ), `space@ spacec@` ( lo -- x ) | младшие `fc-abits` бит lo; выше — данные программы (блок 2, бит `fc-d`); конец lo + n — `fc-abits` + 1 бит от суммы из тех же бит |
| `@ ! c@ c!` | номер ячейки a[2:19) (и для байта смещение байта); выше — начало памяти программы: адрес берётся по модулю размера памяти, проверок адреса нет |
| `execute` | xt — номер слова: 11 бит в бит 11 ссылки; остальное — `fc-etab`: переход только в слой таблицы входов, а он ведёт на вход слова |
| возврат (`exit`, конец `;`) | номер точки возврата со стека возвратов: 13 бит в бит 11 ссылки, двумя строками в двух слоях, обе из одного слова (первого слова пары); остальное — `fc-rtab`: переход только в слой таблицы возвратов, а он ведёт в ячейку после вызова |
| вызов умножения и деления | то же для продолжения (номер из пула ссылок в данных, которые программа тоже может записать) |
| `long!` `long@` ( p0 p1 p2 p3 lo hi -- ) | интервал данных `lo`, `hi` — младшие `fc-abits` бит каждого; ячейки позиции (адресное пространство хоста, `lay-cells` = 4) — значения, в запрос идут как значения; заголовок запроса — копия шаблона из кода (раздел ниже) |
| ячейка понятия слова в программе замены | вход определения из записи слова в данных: младшие 29 бит двумя слоями; `replace` пишет данные, код остаётся |

Ширину интервала (32 бита у `space! space@`, 8 у `spacec! spacec@`) задаёт слово, программа даёт
только начало (7.2.23); конец lo + n делает сумматор. Код программы (блок 0) пишет только компилятор:
`space!` до блока 0 не достигает; `space@` читает только данные программы; ядро не называется ни одной
строкой программы.

**xt — номер слова.** В программе ядра `[']` даёт номер записи слова в словаре (у синонима — номер слова,
которое он называет), а компилятор строит таблицу входов: слой слова с номером i лежит в верхней половине
блока кода по адресу `fc-etab-at` i и ведёт на его вход (в программе замены это ячейка понятия слова).
`execute` копирует номер в ссылку слоя `fc-ex`, остальное поле у неё `fc-etab`: переход возможен
только в таблицу, а таблица — только в слова; число без слова (данные, кроме номеров слов) попадает в пустой
слой таблицы или в чужое слово и ядра не достигает. Цена: один слой (`execute` 24 → 25 тактов).
Ядро (`fc-guard` ноль) и хост по-прежнему называют слово адресом: ядро запускает программу по адресу её входа.
Прежний вход слова в узле стека определений замены адресом не исполнить.

**Точка возврата — номер.** В программе ядра вызов (слова, `execute`, умножения и деления) кладёт на стек возвратов не адрес ячейки после себя, а номер точки возврата — число от 0,
в первом слове пары ссылки (`fc-ret-link`, второе слово не читается). Компилятор строит таблицу возвратов: слой точки с номером n лежит в верхней
половине блока кода по адресу `fc-rtab-at` n (за таблицей входов, с ней не пересекается) и ведёт в ячейку после n-го
вызова. Возврат (`exit`, `;`) копирует `fc-rbits` бит номера в оба поля ссылки перехода трамплина (как `execute`: два слоя, длина интервала всегда один слой), остальное поле у неё
`fc-rtab`: переход возможен только в слой таблицы, а таблица — только в ячейки после вызовов. Число, которое программа записала
на стек возвратов (`>r`, `space!`), попадает в пустой слой таблицы (программа останавливается) или в другую точку
возврата своего кода, но не в середину слова, не в данные-шаблоны в коде и не в ядро. Второе слово пары не читается: пара из двух разных чисел возвращает по первому, код не искажается. Больше 8192 вызовов в программе —
ошибка компиляции -8. Цена: два слоя на возврат. Ядро и компилятор как программа (`fc-guard` ноль) по-прежнему кладут адрес.

**Область `space!`/`space@`.** Это нижняя половина блока данных (28 бит): регистры, таблицы, стеки и память
программы лежат в ней, старшие биты адреса игнорируются (`2^30 + 2^28 + x` и `x` — одна позиция). Весь блок
(29 бит) дал бы запись, выходящую за конец блока на n − 1 бит, то есть в начало блока 3 (данные ядра).
Чтобы взять весь блок: поставить `fc-abits` равным `fc-bbits` и оставить пустым первое поле блока данных ядра
(его раскладка `fc-sp`, `fc-rp` с нулевого бита сдвигается минимум на 32 бита). Больше ничего не менять:
слово непересечения берёт ширину из строк.

Копирование с вычисляемой позицией в слое одно (строка `space!` одна в слое; `spacec@` очищает старшие
24 бита результата в слое между вписыванием и строкой; `execute` и возврат — в слое трамплина без других
строк). Вписывания таблиц, стека и памяти (до 24 бит) — индексы, их места в слое решает планировщик (3.7.2).

Слово ядра (`kn-put`, `kn-get`), скомпилированное с `fc-guard` ноль, вписывает все биты: `space!` пишет
`lo` целиком и `lo + n` суммой в 32 бита. Проверок в `kn-put` нет: позиции ему даёт компилятор.

## Слово непересечения (3.7.5)

`dj-prove ( first end -- flag )` (`backend.fth`) читает слои программы, как они лежат в пространстве
(ячейки first … end - 1; чтение — слово из `dj-reader`: в ядре `kn-get`, в тестах на хосте — чтение
из образа), и доказывает три правила для четырёх блоков пространства (программе принадлежат блок
кода 0 и блок данных 2):

1. каждая строка — пустая операция, копирование двух полуинтервалов одной длины, каждый целиком в
   одном блоке программы, или строка канала (stdin в данные, данные в stdout);
2. копирование в слои (его назначение — поле строки слоя кода от второй ячейки, вписывание при
   исполнении) пишет внутри одного поля, а широкое (дальше 24 бит от начала поля: позицию задаёт программа,
   а не индекс таблицы, стека или памяти) получает от программы только младшие биты поля: выше стоит блок
   постоянной части строки, конец досягаемости (а у начала полуинтервала в данных — длина строки над ним)
   лежит в этом блоке, и ни у одной другой строки слоя нет позиции в этом блоке — строка стоит в слое одна.

3. длинное копирование (18.24, раздел «Длинное копирование в программе ядра» ниже): единственная строка в SYS копирует блок запроса
   (`lay-req`, `lay-rec` + `lay-cap` бит) целиком, строка из SYS пишет в данные (как stdin), а единственная строка, пишущая в заголовок
   блока (первые `lay-hdr` = 56 бит: op, chan, flags), — копия шаблона из кода (блок 0), первый байт которого 6 (LONG).

Непересечение строк слоя слово не доказывает: его соблюдает составитель расписаний при построении
(`lay-row`, 3.7.2); доказательство его повторяло бы и стоило 40 % слова (226 млн тактов на 37 программ).

`kn-compile` вызывает слово после компиляции программы, до её запуска, для слоёв программы, для таблицы
входов и для таблицы возвратов; нарушение — ошибка компиляции -9 («error -9 at СЛОВО»), программа не исполняется. Цена — при
компиляции, при исполнении нуль: см. `docs/measurements/dynamic-isolation.md`.

`tests/test_disjoint.py` (на хосте, быстро): 37 программ, программа слов с вычисляемой позицией, программа длинного копирования и программа
замены проходят; те же, скомпилированные на всё пространство (возврат пишет 32 бита), — нет
(правило 2); построенные в образе нарушения отвергаются с номером правила: ссылка и копия в блоке ядра, две
длины, канал не stdin/stdout, интервал через границу блока, слой таблицы входов или таблицы возвратов в ядро, начало назначения в
верхней половине данных, вписывание в 29 бит вместо 28, 32 бита в номер слова или в номер точки возврата, вписывание через границу
поля, строка данных в слое позиции программы; для длинного копирования (правило 3) — заголовок из данных, из шаблона, первый байт которого не 6,
записанный частью, строка в SYS из другого места данных, другой длины, из кода, приёмник ответа в ядре и вписывание приёмника в 29 бит.

## Длинное копирование в программе ядра (18.24)

`long!` и `long@` ( p0 p1 p2 p3 lo hi -- ) копируют биты данных `[lo, hi)` в адресное пространство хоста с позиции `p` и обратно
(`doc/language.md`, `fc-long`). Запрос — запись LONG (216 бит: op 8, chan 32, flags 16, arg 32, off `lay-pos` = 128; `HOST_POS_BITS` в `proto.def`) в канал SYS. Построение
(`fc-long-kernel`, `forthc.fth`) такое, что изоляция следует из него, а слово непересечения (правило 3) это доказывает:

- **Блок запроса** лежит в данных программы, в верхней половине блока 2: `lay-req` = 2^30 + 2^28 + 1024 (`backend.fth`). Позиции,
  которые программа вычисляет (`space!` и другие), до него не достают (28 бит и n − 1 бит за границей), записать в него может
  только строка, которую поставил компилятор. В блоке: заголовок (`lay-rec` = 216 бит) и сразу за ним `lay-cap` = 65536 бит данных.
- **Шаблон** — ячейка кода из двух строк-пустых-операций (`sl = sh`; слово их пропускает как слои, исполнение ничего не делает), в полях
  `dl`, `dh` которых лежат первые `lay-hdr` = 56 бит заголовка: op 6 (LONG), chan 0, flags 0 (в `long!`) или 1 (в `long@`). Ячейка
  недостижима: переходы — только в таблицу входов, таблицу возвратов и по ссылкам компилятора (то же рассуждение, что для ячеек
  шаблонов вызова на хосте, `docs/measurements/host-layout.md`, раздел 11).
- **Заголовок** пишут: копия шаблона (56 бит, из кода), `arg` (длина, 32 бита) и `off` (позиция, `lay-cells` ячеек по 32 бита, каждая в своём слое) — значения из
  регистров программы. Op, chan, flags программа не даёт и не может изменить.
- **`%lw` ( p0 p1 p2 p3 lo n -- )**: слои «вписывание `lo` (28 бит) и `lo` + `lay-cap` (29 бит) в строку P», «аргумент и шаблон», `lay-cells` слоёв «ячейка позиции»,
  строка P (`[lay-req + lay-rec, +lay-cap)` ← `[lo, lo + lay-cap)`, одна в слое: правило 2), строка в SYS (весь блок). Программа даёт
  `lo` и `n`; из данных уходят первые `n` бит, остальные биты окна хост не берёт (`arg` = `n`).
- **`%lr` ( p0 p1 p2 p3 lo hi n -- )**: те же слои заголовка, строка в SYS, затем строка приёмника `[lo, hi)` ← SYS (в программе вписываются
  младшие 28 бит `lo` и `hi`, строка одна в слое). Ответ хоста попадает только в нижнюю половину данных.
- **Слова** `%lst`, `%lld` (`long!`, `long@`; цена `fc-forbid`) на языке: `long!` шлёт кусками по `lay-cap` бит, двигая позицию с переносом между ячейками
  (перенос за область — остаток теряется, как в эмуляторе); `long@` — одним запросом. Пустой или перевёрнутый интервал — ничего.
  В ядре число 65536 бит на запрос и блок в верхней половине данных — расход памяти программы, не ограничение длинного копирования.

Что доказывает слово (правило 3): строка в SYS копирует `[lay-req, lay-req + lay-rec + lay-cap)` и только его; строка из SYS пишет
в блок 0 или 2 (как stdin, дальше правила 1–2 для вписываний); строка с приёмником, пересекающим `[lay-req, lay-req + lay-hdr)`, — это
копия `lay-hdr` бит из блока 0, первый байт источника (читается из образа) — 6. Вписывания в строки SYS слово не отслеживает (узкое
вписывание в целевую строку оно не читает): их нет, компилятор не ставит их по построению. Что строка шаблона и строка запроса идут подряд
без точек входа между ними, слово не доказывает (как для вызова на хосте, 18.22): между ними нет ни вызова, ни перехода, ни
`execute`; положение вписываний в блок запроса недостижимо для программы, потому что все они — строки компилятора.

Пробы (`tests/test_isolation.py`, `long_probes`; хеш верхней половины данных не включает блок запроса, а первый байт заголовка после
прогона — LONG): подложенная запись EXEC уходит как данные (EXEC не исполняется: метка не создана), аргументы вне допустимых ничего
не меняют, ответ хоста поверх стека возвратов подкладывает пару — возврат идёт в точку возврата, не в слой запроса; ядро цело.

## Пробы на L0

`tests/test_isolation.py` (`make -C language check-isolation`) даёт L0 программы-пробы: каждая
делает нападение, если её ввод 1, и ничего, если 0 (текст один, поэтому ядро компилирует его в то же
состояние). Эмулятор — копия `emulator/src`, собранная пробой, — печатает при выходе хеш блоков 1 и
3 (ядро) и верхних половин блоков 0 и 2. Проба проходит, если хеш ядра после нападения равен хешу
после контрольного прогона (ядро не исполняется, пока работает программа, и не менялось), а верхние
половины блоков программы (там у программы ничего нет) не записаны (в верхней половине данных, кроме блока запроса длинного копирования,
который пишут только слова `long!`, `long@`; его проба не хеширует, а проверяет первый байт заголовка: LONG).

| Проба | Что происходит |
|---|---|
| `space! spacec!` по 8 позициям, называющим блоки 0–3 и их верхние половины | запись попадает в данные программы: старшие биты игнорируются (последняя запись читается из общего места, `80`) |
| `space! spacec!` по записи константы и входу слова ядра | то же: программа продолжает работать |
| `space@ spacec@` по тем же 8 позициям | читаются данные программы (`77777777`), не ядро |
| `@ ! c@ c!` по адресам блоков ядра | память программы, не ядро |
| `execute` входа `fc-.n` как числа | слой таблицы входов: программа не возвращается, ядро цело |
| `execute` данных, 0, -1 | слой таблицы входов или пустой слой; может не кончиться: прогон режется по тактам (400 млн) |
| возврат по адресу ядра или данных (`>r`, подложенная пара) | пустой слой таблицы возвратов или другая точка возврата: управление в код программы не попадает в середину |
| возврат, записав пару в стек возвратов (`space!`): номер точки, номер без точки, номер конца, адрес ячейки в середине слова (одно слово пары, пара из двух номеров, старая пара адресов) | управление идёт в точку возврата с этим номером (пропущен вызов), в конец или в пустой слой; в середину слова не идёт (до 18.22 пара адреса шла в ячейку середины слова и исполняла его слои) |
| `long!` записи EXEC, собранной в данных | запись уходит в файл как данные, EXEC не исполняется (метка не создана); заголовок запроса — LONG |
| `long!` и `long@` с неизвестной областью, позицией в области за 2^64 бит и через конец области, перевёрнутым и пустым интервалом, интервалом на границе области данных | ничего не меняют, ядро цело, заголовок запроса — LONG |
| `long@` поверх стека возвратов (ответ хоста — пара номеров) | возврат идёт в точку возврата, как при записи пары `space!`; не в слой запроса |

Вывод контрольного прогона и нападения проба сверяет с таблицей `probes()` теста.

- `%link` замены (запись в слой кода программы);
- правило «непересечение строк слоя» слова непересечения.

Потоки 37 программ на хосте равны модели (`STREAMS=equal`); у программ с `space!`, `space@` другая форма
(без hi, с сумматором).

## Открытое (решения автора ждут)

- Область `space!` — 28 бит, поведение `execute` с числом, не называющим слово, — как описано выше.
- Вписывания в строку SYS слово не ищет: узкое вписывание (до 24 бит) в строку запроса оно не читает; компилятор их не ставит, по
  построению. Если нужно доказывать — читать целевую строку каждого вписывания (+ порядка 1 % тактов доказательства).
