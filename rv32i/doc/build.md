# Сборка, ABI и восстановление

Основной формат — каталог vm2-direct-v1 с image.bin, boot.bin, manifest.json,
map.json. Манифест содержит rv32i-direct-v1: объём памяти, регионы регистров
и гостевой памяти, смещения PC/status/exit, интервал checkpoint и карту
счётчиков. Физические адреса прежнего контейнера не являются ABI прямого пути.

По умолчанию гостевая память — 64 КиБ с нулевого адреса, регистры — 32 бита,
машинный код и память little endian. Поддерживаются все 40 инструкций RV32I;
инструкции выровнены на 4 байта, данные — на свою ширину. Причины остановки
и ECALL 63/64/93 сохраняют логический контракт rv32i.md и rv32i_io.md.
Ширины SYS берутся из целевого протокола vm1 после размещения.

`rv32i build` принимает raw машинный код. `build-c` использует собственный
runtime/rv32i и явный freestanding GCC RV32I/ILP32 без libc. Это подготовка
гостя на хосте. `run` загружает готовый boot через stdin vm1, пересылает ввод
и возвращает exit & 255. Ошибка исходника/артефакта возвращает 2, исключение
или физический лимит без полного снимка — 125. Хост не декодирует RV32I.

```sh
./rv32i build program.bin -o /tmp/cooperative --checkpoint-every 1
./rv32i run /tmp/cooperative --snapshot /tmp/commit.bin < input
./rv32i resume /tmp/cooperative /tmp/commit.bin -o /tmp/continued
./rv32i run /tmp/continued --snapshot /tmp/next.bin < remaining-input
```

Пауза возвращает 75. Снимок содержит согласованные границы псевдоинструкций,
данные обновлений, регистры и продолжение fetch после commit. Общий механизм
checkpoint_stop принадлежит vm2, передача и размещение — vm2/copycode.
Монитор RV32I считает собственные commit и байты IO. Счётчики uint32
циклические; задания длиннее 2^32 байтов/commit требуют внешнего учёта.
Позиции файлов, закрытые устройства и внешние процессы восстанавливает
вызывающая сторона. Старые сырые snapshots сюда не импортируются.

VM1_ROOT, VM2_ROOT и COPYCODE_ROOT задают объявленные зависимости.
Самостоятельный архив включает их исходные снимки, лицензии и SHA256.
`make distcheck` распаковывает комплект в путь с пробелами, собирает vm1
и аудитор, проверяет RV32I/IO/C, монитор, запуск без исходника, повторную
упаковку и clean. Сетевой загрузки нет. RISCV_CC задаёт внешнюю установку
GCC. Загруженный локальный toolchain не включается в архив и сохраняется clean.

Старые tests/test_rv32i*.py сохранены как legacy-проверки прежнего C-эмулятора.
Основной набор — test_direct/test_monitor/test_cli/test_schedule. Аудитор
проверяет каждый физический такт: все операнды, включая src/src, канальные
буферы, fetch и патченные адреса. Поля и память сравниваются с независимым
RV32I-эталоном; стандартный бинарник vm1 проверяется дополнительно.

План ускорения 8.6: исходные операции блоков группируются общим интервальным
планировщиком copycode до lower в vm1. Все зависимости RAW/WAR/WAW и src/src
сохраняются; динамические операции, каналы и переходы служат границами.
Последовательное расписание остаётся явно доступным для парных проверок.
