# copymachine

Общий исходный репозиторий vm1, vm2, copycode, RV32I и pForth.
План работ — [ROADMAP.md](ROADMAP.md).

Активные компоненты находятся в `vm1/`, `vm2/`, `copycode/`, `rv32i/`
и `pforth/`. `copy-space/` содержит переходную интеграцию и совместимые
ссылки. Унаследованные реализации находятся физически в
[`legacy/`](legacy/README.md). Рабочие исходники двухфазного backend vm1,
общие форматы и закреплённый upstream pForth остаются зависимостями активного
кода; происхождение и лицензии сохранены в проектах.

В этой рабочей среде корневой `.git` защищён от записи. Метаданные общего
репозитория размещены в `.project-git`; обычные команды доступны через:

```sh
./project-git status
./project-git log --oneline
./project-git diff
```

В обычном клоне Git создаёт стандартный `.git`; там доступны также команды
`git status`, `git log` и остальные без обёртки.

Это локальный Git-репозиторий без нового remote. Прежние Git-каталоги
сохранены в `legacy/git/`; исходники включаются в общий репозиторий обычными файлами,
а не gitlink/submodule. Сборки, кэши, старые Git-метаданные и локальные
настройки в новую историю не включаются.

```sh
make -C vm1 -j1
make -C rv32i -j1 check-machine
make -C pforth -j1
python3 vm2/tools/limited_run.py --seconds 600 --memory-mib 768 ./pforth/pforth run pforth/build/pforth
```

Проверки запускать последовательно с ограничениями ресурсов.
Карта переноса и проверки сохранности — `legacy/MIGRATION.json`.

Каждый компонент сохраняет свою лицензию; единая история не меняет условия
MIT, Apache-2.0 и лицензии upstream-зависимостей.
