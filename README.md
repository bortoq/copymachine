# copymachine

**EN.** copymachine is a computer whose only action is copying bits from one place to another. It has an emulator of this "copy space" and languages that compile themselves inside it. The text below explains the project part by part in Russian; details are in the documents it links to.

Этот документ — обзор проекта по частям, от основы к планам. Каждая часть — несколько абзацев; подробности вынесены в другие документы, ссылки — в конце частей. Точные определения понятий — в [словаре](docs/dictionary.md#понятия).

## Часть 1. Одно действие — копирование

Обычный компьютер умеет много разных действий: сложить, сравнить, перейти, записать в файл. Здесь действие одно: **взять несколько подряд лежащих битов и записать их в другое место**. Всё остальное — сложение, ветвление, цикл, вызов, вывод на экран — получается из копирований, расставленных в нужном порядке.

Зачем так:

- **Малая основа.** Чтобы поверить в работу всей системы, надо проверить одно действие, а не сотни.
- **Параллельность.** Копирования, которые не задевают общих битов, не зависят друг от друга: их можно выполнять одновременно и даже на разных машинах.
- **Честная цена.** Стоимость вычисления видна прямо: сколько бит, сколько копирований, сколько шагов.

Цель проекта — одна вычислительная система, где любое вычисление — копирования: короткие внутри одного пространства, длинные — с оборудованием компьютера, дальние — между компьютерами.

## Часть 2. Пространство, процессор, такт

**Пространство** — длинная строка битов, пронумерованных с нуля. Больше ничего в машине нет: и программа, и данные, и стек — участки этой строки.

**Строка копирования** — четыре числа `dl dh sl sh`: «биты с `sl` до `sh` записать на место с `dl` до `dh`». Строка, у которой нечего копировать, — **NOP** (ничего не делает).

**Процессор** — первые P строк пространства. За один **такт** машина читает все строки процессора и выполняет их копирования **одновременно**. Записанное видно со следующего такта. Строки, выполняемые за один такт, называются **слоем**.

Процессор — тоже часть пространства, поэтому копирование может переписать строки процессора. Так устроено всё управление:

- **переход** — последняя строка слоя копирует в процессор следующий слой;
- **ветвление** — какой слой копировать, выбирается по данным;
- **останов** — в процессор копируются одни NOP.

**Непересечение.** В одном такте никакие два копирования не должны задевать общих битов. Тогда порядок внутри такта не важен и результат всегда один.

## Часть 3. Как из копирований получается вычисление

Главный приём — **таблица**. Функция с небольшим входом записывается всеми своими значениями подряд. Чтобы вычислить её, значение входа копируется внутрь строки (в поле «откуда»), и строка копирует нужную запись таблицы. Так делаются сложение, сравнение, логические операции: например, сложение 32-битных чисел — 8 обращений к таблице сложения 4-битных чисел, соединённых переносом.

Этот же приём — «вписать число в строку, а потом выполнить строку» — даёт доступ к данным по вычисляемому адресу (массивы, стеки) и выбор следующего слоя (ветвление).

## Часть 4. Эмулятор

Настоящей машины копий пока нет, поэтому её изображает **эмулятор** — программа на C (около 1 300 строк, `emulator/`). Он читает со стандартного ввода **образ** — начальное содержимое пространства — и исполняет такты, пока процессор не станет из одних NOP.

Связь с внешним миром идёт через **каналы**: особые номера вместо адреса означают stdin, stdout, stderr и служебный канал **SYS** — запросы к **хосту** (компьютеру, на котором запущен эмулятор).

Режим `checked` после каждого такта независимо проверяет непересечение — им ловят ошибки компиляторов.

Подробнее: [глава 2 руководства](docs/guide/02-emulator.md), [README эмулятора](emulator/README.md).

## Часть 5. Язык

Писать программы прямо строками копирования неудобно. Поэтому над эмулятором стоит язык, который переводит текст в копирования. Язык проекта — **цепочка вложенных языков** (`tower/`): несколько маленьких языков, каждый добавляет немного слов, а его компилятор переводит текст в язык ниже. Единственное описание языка — [tower/README.md](tower/README.md); здесь только обзор. Прежний язык (бут через pForth, ядро, образ L0) удалён из `main` (архив, тег `archive-2026-11-10`).

## Часть 6. Цепочка языков

### Языки

| Язык | Что добавляет | Пример слов |
|---|---|---|
| 1 | одна строка копирования, записанная числами | `r dl dh sl sh` |
| 2 | короче запись (три числа), данные, имена мест (метки) | `copy`, `data`, `:имя`, `&имя` |
| 3 | таблицы, блоки, переходы, вызовы, ввод-вывод, арифметика на таблицах | `table`, `lut`, `block`, `goto`, `if`, `call`, `emit`, `add` |
| 4 | длинное копирование — обмен с хостом | `copy` с адресом хоста (`0x1` + 32 цифры) |
| 5 | цена программы | `cost`, `price` |
| Форт | обычный язык программирования сверху | `: ; if then dup + emit` … (64 слова) |

Языки 1–3 — это ассемблер машины копий: на них удобно писать компиляторы, но не обычные программы. Обычные программы пишут на Форте.

### Программы цепочки и порядок их работы

Каждый компилятор цепочки — **отдельная программа**, которая работает в **своём пространстве** (до 1 Мбит). Одна программа не вместила бы всё, поэтому работа разделена на шаги — **проходы**. Каждый проход читает текст со stdin и пишет результат на stdout:

```
текст на Форте
   │  forth   — переводит Форт в язык 3
   ▼
текст языка 3
   │  l4c     — только если в copy есть адрес хоста: строит запросы к хосту
   │  l3c     — компилятор языка 3: слова, таблицы, блоки → язык 2
   │  l3p     — по желанию (слово pack): плотнее раскладывает строки по тактам
   ▼
текст языка 2 с именами
   │  l2l     — заменяет имена (метки) числами → язык 1
   ▼
текст языка 1
   │  seed    — зерно: превращает числа в биты → образ
   ▼
образ ──► эмулятор ──► вывод программы
```

| Программа | Что делает |
|---|---|
| `seed` | **зерно**: текст языка 1 → образ |
| `l2l` | имена → числа (язык 2 → язык 1) |
| `l3c` | компилятор языка 3 (→ язык 2) |
| `l4c` | проход адресов хоста в `copy` (перед `l3c`) |
| `l3p` | проход упаковки по тактам |
| `forth` | компилятор Форта (→ язык 3) |
| `forthgen` | строит таблицы для `forth` из списка его слов |

### Самосборка

Все эти программы написаны на языке 3, поэтому цепочка собирает сама себя: `l3c` компилирует собственный текст, результат проходит `l2l` и `seed`, и получается тот же образ `l3c` байт в байт. Круг идёт около 30 секунд.

Начало круга пока даёт Python: им сделан самый первый образ `seed`. Python в проекте ещё служит эталоном для сверки и тестами; его уберут последним этапом — на хосте останутся только эмулятор, `sh` и `make`.

### Чего пока нет

- **Подкачки.** `l3c` занял 98 % своего пространства. Новые слова (стек, рекурсия) пойдут через подкачку на длинных копированиях: нужное копируется с хоста, когда нужно. Опыт сделан (23.18–23.19, на паузе); как встроить подкачку в устройство уровней — решает автор (журнал дизайна, 7.2.34–7.2.35).
- **Интерактивности.** Сейчас всё собирается целиком и запускается. Позже компилятор будет жить постоянно и компилировать по одному определению.

Все слова всех языков, примеры, сборка и что пока делает Python — в [tower/README.md](tower/README.md); замеры — в [docs/measurements/tower.md](docs/measurements/tower.md).

## Часть 7. Выход наружу и цена

**Длинное копирование** — копирование между пространством программы и хостом. Для этого весь хост — одно большое адресное пространство: позиция в нём — 128 бит. В нём есть часы, файлы и устройства, указанные при запуске эмулятора; можно прочитать или записать любой бит файла. Ошибок нет: чтение за пределами даёт нули, запись туда пропадает. Подробнее: [глава 4 руководства](docs/guide/04-long-copy.md).

**Цена** — сколько стоит программа: строки, слои, биты, такты. Цена сравнивает варианты одной и той же программы (например, обычную и упакованную раскладку), и выбирается дешёвый. То, что пока не решено, получает **запретительную цену** — заведомо большую любой настоящей. Это приём вместо ошибок и исключений.

## Быстрый старт

Нужны POSIX, `cc`, Python 3.11+, make.

```sh
make              # эмулятор
make check-fast   # тесты эмулятора и цепочки языков (несколько минут)
make check-tower  # только цепочка
```

Остальные цели (`check-full`, `check-tower-long`, `lint`), CI и раскладка каталогов — в [указателе документов](docs/README.md) и [docs/layout.md](docs/layout.md).
